# Amaya Hub

Монорепозиторий веб-инструментов Amaya. Сейчас в нём сервис локализации — единое место,
где живут все тексты продуктов и откуда они выгружаются в код, в Figma и доступны нейросетям по MCP.

```
apps/central-hub/      сервис локализации (Nuxt 4, Nuxt UI 4, Tailwind 4)
packages/l10n-core/    правила ключей и форматы файлов локалей — общие для сервера, CLI и MCP
packages/l10n-cli/     CLI amaya-l10n: pull / diff / check / import
packages/figma-plugin/ плагин Figma «Amaya Hub — локализация»: переменные из сервиса, живое обновление
supabase/              миграции базы (Supabase CLI)
fixtures/legacy/       копии файлов локалей InApp и Pages Hub — для автотеста выгрузки
tests/db/              автотесты базы: права, правила ключей, история, импорт и выгрузка
tests/unit/            код без базы: выгрузка в GitHub на поддельном API, история ключа, подсказки к ключу
```

Внутри `apps/central-hub/app` общее вынесено из компонентов:

```
composables/   useLocalizations — грид и фильтры; useLanguages, useKeyTree, useExportRules — данные,
               общие для нескольких мест (по одному запросу на страницу); useNotifyError, useCopy
utils/         чистые функции без Vue: история ключа (history), подсказки к ключу (keySuggestions),
               даты (formatDate), множественное число (plural) — покрыты tests/unit
```

На сервере маршруты `server/api/**` объявляются через `defineHubHandler` (`server/utils/db.ts`):
`HubError` и ошибки базы уходят человеку понятным текстом без `try/catch` в каждом маршруте.

Решения, принятые по ходу работы, — в [DECISIONS.md](DECISIONS.md).

## Как устроен доступ

- Сервис закрыт общим паролем (`NUXT_HUB_PASSWORD`) и спрашивает имя — им подписываются правки в истории.
- Браузер **только читает** из Supabase публичным ключом: ключи, языки, справочник.
  Права на запись и вызов изменяющих функций у публичного ключа отобраны миграцией `lockdown`,
  это проверяет `tests/db/security.test.ts`.
- Все изменения идут через серверные маршруты `apps/central-hub/server/api/*` с секретным ключом.
- Строки не удаляются — только помечаются устаревшими. Правила имени ключа проверяет сама база.

## Установка

Нужны Node.js 22 и pnpm 10 (`corepack enable` или `npx pnpm@10.33.2 …`).

```bash
pnpm install
cp .env.example .env   # и заполнить значения
```

## Команды

```bash
pnpm dev          # сервис на http://localhost:3000
pnpm build        # сборка apps/central-hub
pnpm lint
pnpm typecheck
pnpm test         # unit-тесты packages/* и tests/unit
pnpm db:start     # локальный Supabase в Docker: миграции с нуля (нужен запущенный Docker Desktop)
pnpm test:db      # тесты базы — только на локальном Supabase, строки InApp и Pages Hub берутся из fixtures
pnpm test:stand   # права настоящего стенда из .env: публичный ключ ничего не может записать
pnpm db:stop      # остановить локальный Supabase и стереть его данные
```

`test:db` против основной базы не запускается: тесты импортируют копии файлов InApp и Pages Hub,
а импорт заменил бы правки людей в этих строках значениями из файлов. `test:stand` безопасен —
он только пытается писать публичным ключом и ждёт отказа.

## CI и бэкапы

- `.github/workflows/ci.yml` — на каждый push в `main` и PR: unit-тесты и тесты базы на свежем
  локальном Supabase. Секреты не нужны.
- `.github/workflows/db-backup.yml` — дамп основной базы раз в сутки (05:00 МСК) и по кнопке
  Run workflow: роли, схема и данные, артефакт `db-backup-<дата>` хранится 30 дней.
  Нужен секрет `SUPABASE_DB_PASSWORD` — пароль базы, тот же, что в `.env` (Settings → Secrets and
  variables → Actions). Адрес **Session pooler** workflow собирает сам: прямой адрес базы доступен
  только по IPv6, а раннеры GitHub его не умеют. Вместо пароля можно положить готовую строку
  подключения Session pooler — в `SUPABASE_DB_PASSWORD` или `SUPABASE_DB_URL`.

Восстановление в новый проект Supabase (из скачанного и распакованного артефакта):

```bash
psql "$NEW_DB_URL" -f roles.sql -f schema.sql \
  -c 'SET session_replication_role = replica' -f data.sql
```

Только данные сервиса (схема `public`) — в базу, где миграции уже применены: очистить таблицы
`public` и загрузить из `data.sql` блоки `COPY "public".…` с `session_replication_role = replica`.
Так проверен дамп от 28.10.2026: ключи и переводы совпали с основной базой до байта.

## База

Миграции лежат в `supabase/migrations` и применяются Supabase CLI:

```bash
pnpm exec supabase login                               # один раз
pnpm exec supabase link --project-ref <project-ref>    # один раз, спросит пароль базы
pnpm db:push                                           # применить новые миграции
pnpm db:new <name>                                     # создать миграцию
```

Справочники (языки, коды игр и сайтов) — тоже в миграциях, seed не используется:
строки приходят импортом из InApp и Pages Hub.

## Создание ключей

Кнопка «Новый ключ» над гридом. Схему помнить не нужно: под полем «Ключ» — подсказки к следующей части
(↑ ↓ — выбрать, Enter или Tab — подставить, Esc — скрыть):

- пустое поле — начала с пояснениями: `app.` — игра, `web.` — сайт, `common.` — общее…;
- после `app.`, `web.`, `brand.`, `test.` — коды из справочника; нового кода нет — «+ добавить игру
  в справочник», название подставляется само (dino → Dino), Enter — добавить;
- дальше — разделы, которые уже есть, и типичные (`paywall`, `onboarding`, `banner` у игры).

Открыт раздел в дереве — ключ начинается с него. Пробелы, дефисы и заглавные сразу становятся
snake_case. Пока ключ дописывают, ошибок нет; красным — только то, что дописыванием не исправить
(`legacy.`, язык в ключе, занятое имя), или когда ушли из поля.

В форме только ключ, описание (обязательно, от 10 символов) и теги. Имя проверяется по правилам
«Как называть ключи» (`packages/l10n-core/src/keys.ts`, те же правила держит база). Рядом — похожие
строки по ключу (`pg_trgm`): сначала стоит взять существующий ключ. Ключ создаётся без текстов: их
вписывают потом в гриде или через MCP — там же проверка подстановок, экранирования `@ { } | $`, HTML
и капса (`text-checks.ts`). Лимит длины задаётся в панели ключа («Изменить»). Тексты из интерфейса —
черновики (`draft`). После создания поиск показывает весь раздел (`app.farm.banner.`) — новый ключ
вместе с соседями, сам ключ открыт в панели.

## Редактор

`/localizations` — дерево разделов слева, грид в центре, панель ключа справа.

- **Отметки в ячейках:** ✦ — перевод от ИИ, серая точка — черновик, оранжевая — перевод устарел
  (английский сейчас другой, чем тот, с которого переводили). У утверждённых отметки нет; подробности — в подсказке ячейки.
  Правку вернули как было — метки снимаются сами: текст, совпавший с утверждённым, снова утверждён, а переводы
  после отката английского не устаревают.
- **Фильтры** — статус (в том числе «Не утверждённые»: черновики и тексты от ИИ вместе — то, что не уходит
  в выгрузку в код), «нет перевода на язык», «перевод устарел», изменённые за неделю, раздел из дерева,
  поиск и теги. Всё лежит в адресе страницы: «Ссылка на выборку» копирует его, коллега откроет то же самое.
- **«Ключ устарел»** — отдельная выборка ключей, помеченных устаревшими, то есть выведенных из употребления
  (их нет в таблице и выгрузках). Таблица в ней только для чтения; выделенные ключи можно вернуть кнопкой «Вернуть».
  «Перевод устарел» и «ключ помечен устаревшим» — разные вещи: первое про перевод одного языка,
  второе про ключ целиком. Устаревший ключ не занимает имя: если `app.farm.banner` был строкой, после
  пометки внутри можно создать `app.farm.banner.title`. Вернуть такой ключ нельзя, пока его место занято.
- **Панель ключа** открывается кликом по ключу или Enter на колонке ключа и идёт за активной строкой.
  В ней описание, теги, лимит, тексты со статусами, «Утвердить» по языку и «Утвердить всё», история
  и копирование ключа и `t('…')`. История — карточка на действие: одна правка (импорт 9 языков, «Утвердить всё»)
  одной карточкой со сводкой, по клику — подробности по языкам; видно последние 10, дальше «Вся история (N)» порциями по 20. У строк InApp и Pages Hub `t('…')` берёт путь из кода проекта
  (`legacy_path`), а не ключ сервиса. Утверждение снимает «устарел» и отправляет текст в выгрузку в код:
  пока правку не утвердили, под текстом видно, что сейчас в проектах.
- **Утвердить пачкой:** выделить строки в гриде → «Утвердить» — все языки с текстом. Число в кнопке —
  сколько выделенных ключей ещё есть что утверждать, если не все; всё выделенное уже утверждено — кнопки нет.
  «Изменить» правит описание, теги, лимит длины и ссылку на Figma (Ctrl+Enter — сохранить, Esc — отмена);
  проверки те же, что при создании ключа, правки попадают в историю. У строк InApp и Pages Hub
  описание можно оставить пустым. Ключ, помеченный устаревшим, сначала возвращают.
- **Совместная работа:** правки коллег приходят в реальном времени. Если ячейку изменили, пока вы её
  правили, сервер отвечает 409: ячейка показывает текущий текст, тост называет автора и предлагает
  «Оставить мой». Ctrl+Z работает так же — чужую более свежую правку отмена не перезапишет.
- **Очередь перевода** — кнопка над гридом (меню по языкам со счётчиками, с учётом выбранного раздела)
  или `/localizations/queue?lang=de&prefix=app.`. По одной строке без перевода или с устаревшим переводом. Enter — сохранить и дальше, Shift+Enter — перенос, Alt+→ — пропустить,
  Esc — к таблице. Ошибки в тексте (подстановки, лимит, экранирование) не дают сохранить. Если
  устаревший перевод верен, Enter без правок подтверждает его.
- **Ctrl+K / ⌘K** — палитра: поиск ключа по всей базе, «Новый ключ», очередь перевода по языку,
  частые фильтры, тема.

## Настройки

`/settings` — пункт «Настройки» в меню слева. Пока одна настройка — тема: светлая (по умолчанию) или тёмная.
Выбор хранится в этом браузере; переключить можно и из палитры (Ctrl+K → «Тема: тёмная»). Страницы прототипа
`/ab-tests` и `/audit-page` остаются светлыми.

В разметке сервиса — смысловые цвета Nuxt UI (`text-muted`, `bg-default`, `border-default`…), а не `gray-*`
и `white`: они сами переходят на тёмные оттенки. Где точного токена нет — класс с парой `dark:`. Цвета грида
заданы CSS-переменными в `Grid.vue`.

## Figma

Тексты попадают в Figma плагином «Amaya Hub — локализация» (`packages/figma-plugin`): он берёт их прямо
из сервиса, без таблиц и файлов. Тексты и переводы правятся только в сервисе — если поменять текст
прямо в слое, Figma отвяжет слой от переменной, и обновления до него больше не дойдут.

**Установка** (один раз, нужно приложение Figma для компьютера):

1. «Export Figma» над гридом → «Скачать плагин» и распаковать архив. Плагин ходит в тот сервис,
   с которого его скачали: адрес уже прописан в манифесте.
2. В Figma: Plugins → Development → Import plugin from manifest → `manifest.json`.
3. Запустить плагин и вставить токен — значение `NUXT_FIGMA_TOKEN` (только чтение текстов).
   Плагин запоминает его на этом компьютере.

**Работа:**

- В окне плагина выбрать разделы — то же дерево, что слева в сервисе, на любой глубине (например, `common`
  и `legacy → inapp → coloring1`) — и языки, нажать «Загрузить»
  (Ctrl+Enter). Появится коллекция «Amaya Hub»: режим на каждый язык (English, Russian, German…),
  переменная на ключ с именем через `/` (`app/cars2/paywall/title`), описание ключа — описание
  переменной. Перевода нет — пустая строка. Переменная `language` показывает название режима.
- **Живое обновление:** пока окно плагина открыто, он раз в 5 секунд забирает изменения, и правка
  в сервисе появляется в макете сама. Окно можно не закрывать и работать дальше.
- **Обновить без окна:** Plugins → Amaya Hub — локализация → «Обновить тексты», Ctrl+Alt+P (Run last plugin)
  или кнопка «Обновить тексты» в правой панели файла. Берётся выборка, сохранённая в этом файле.
- Переменные обновляются по ключу и не пересоздаются, поэтому привязки слоёв не слетают. Ключи, которых
  больше нет в выборке или которые помечены в сервисе устаревшими, плагин не удаляет, а показывает списком.
- Девять языков — девять режимов: нужен тариф Figma Professional или выше.

Плагин ходит в `GET /api/figma/plugin/sections` и `GET /api/figma/plugin/texts?prefixes=&langs=[&since=]`
с заголовком `Authorization: Bearer <NUXT_FIGMA_TOKEN>`; с `since` приходят только изменения. Проверка плагина
без Figma — `packages/figma-plugin/test` (код плагина на поддельном `figma`).

**Без плагина** — в том же окне «Скачать ZIP»: файл на каждый язык в формате встроенного импорта Figma
(W3C Design Tokens). В Figma открыть Variables, создать коллекцию и перетащить в неё **все файлы сразу** —
каждый станет режимом. Обновлять так неудобно: встроенный импорт обновляет существующие переменные
только по одному режиму. Те же файлы отдаёт `GET /api/figma/export?prefixes=common.,app.cars2.&langs=en,ru`.

## MCP для нейросетей

`POST /mcp` — MCP-сервер (Streamable HTTP без сессий), токен `NUXT_MCP_TOKEN`. Инструменты:
`search_strings`, `get_string`, `find_similar`, `get_key_tree`, `list_registry`, `create_key`,
`write_draft_translation`, `list_untranslated`, `check_text`.

- `create_key` требует описание и не создаёт ключ, если есть похожая строка (≥ 60 %), пока в
  `not_duplicate_reason` не объяснено, чем новая отличается.
- Тексты нейросети сохраняются со статусом «от ИИ» (`ai`). Утверждать, удалять и переименовывать нечем,
  а перезаписать текст человека не даёт сама база (`set_ai_translation`). В код проектов ключ нейросети попадает
  после того, как его утвердит человек.

### Как подключить Claude Code

1. **Получить токен** у владельца сервиса — это значение `NUXT_MCP_TOKEN` из переменных Vercel.
   В репозиторий и в `.mcp.json` токен не кладут.
2. **Сохранить токен в переменную `AMAYA_HUB_TOKEN`:**

   ```bash
   setx AMAYA_HUB_TOKEN "<токен>"                         # Windows
   echo 'export AMAYA_HUB_TOKEN="<токен>"' >> ~/.zshrc    # macOS
   ```

   Claude Code читает переменные при запуске: после этого перезапустить терминал или VS Code целиком.
3. **Положить `.mcp.json` в корень проекта.** В этом репозитории он уже есть, в другой проект его
   можно скопировать и закоммитить — токена в нём нет:

   ```json
   { "mcpServers": { "amaya-hub": { "type": "http", "url": "https://central-hub-sigma.vercel.app/mcp",
     "headers": { "Authorization": "Bearer ${AMAYA_HUB_TOKEN}" } } } }
   ```

   При первом запуске Claude Code спросит, доверять ли серверу `amaya-hub` из `.mcp.json`, — разрешить.
4. **Проверить:** команда `/mcp` в Claude Code — `amaya-hub` подключён, у него 9 инструментов.
   Дальше можно просить словами: «найди в amaya-hub строки про Continue», «создай ключ для заголовка
   пейволла Cars 2».

Если не подключается:

- `/mcp` показывает ошибку или просит авторизацию — Claude Code не видит переменную (не перезапущен после
  `setx`) или токен неверный: сервер отвечает 401 «Неверный токен MCP».
- Ответ 503 «NUXT_MCP_TOKEN не задан на сервере» — MCP выключен на стенде, нужен владелец сервиса.
- Если при первом запуске отказали в доверии — `claude mcp reset-project-choices` и перезапуск.

Подключить сервер сразу во всех своих проектах, без `.mcp.json` и переменной:
`claude mcp add --transport http --scope user amaya-hub https://central-hub-sigma.vercel.app/mcp --header "Authorization: Bearer <токен>"`
— токен сохранится в `~/.claude.json`. Другие клиенты MCP подключаются так же: Streamable HTTP, этот
адрес и заголовок `Authorization: Bearer <токен>`.

## Выгрузка в код

**В код проектов уходят только утверждённые тексты.** У каждого языка база хранит последний утверждённый
текст (`approved`): правка ставит «черновик», а в файлах проекта остаётся прежний текст, пока правку не утвердят.
Новый ключ появляется в файлах после утверждения. Figma (плагин и ZIP) показывает и черновики — это для макетов.

**Какой ключ в какой проект** — по началу ключа (наборы `export_sets`):

| Проект | Ключи |
|---|---|
| InApp | `legacy.inapp.`, `common.`, `app.`, `brand.`, `ds.`, `test.` |
| Pages Hub | `legacy.pages_hub.`, `common.`, `web.`, `brand.`, `ds.`, `test.` |

Служебные `common.selftest.` не уходят никуда. В интерфейсе это видно у начал в подсказках
«Новый ключ» и строкой под полем («Выгрузка в код: InApp»), а также в панели ключа.
Правило одно для выгрузки и подсказок — `keyInExportSet` в `packages/l10n-core`.

### Кнопка «Выгрузить в код» — PR на GitHub

Над гридом «Выгрузить в код» → карточка на каждый набор: репозиторий, что изменится по файлам (`ru.json ~1`),
сколько ключей ждут утверждения, последняя выгрузка. «Показать изменения (N)» открывает окно со всеми строками
«было → стало» по ключам порциями по 200 ключей; клик по ключу ищет его в таблице, Ctrl+Enter — выгрузить. Если изменения в нескольких проектах, внизу окна кнопка для всех сразу — PR в каждый
репозиторий одним нажатием (Ctrl+Enter в окне делает то же). Подпись как у карточек: PR уже открыты везде —
«Обновить у всех (N)», нигде — «Создать PR во всех (N)», по-разному — «Выгрузить во все (N)». «Создать PR» / «Обновить PR #N»:

- сервис собирает файлы набора, сравнивает с основной веткой репозитория и кладёт изменённые файлы
  коммитом в свою ветку `amaya-hub/<набор>` (каждый раз заново от основной ветки);
- открывает PR в основную ветку или обновляет уже открытый — в описании файлы и строки «было → стало»;
- если выгружать стало нечего, закрывает свой PR с комментарием.

В основную ветку сервис не пишет, не мержит и ничего не удаляет: тексты попадают туда, когда человек смержит PR.
Это проверяет `tests/unit/github.test.ts` — поддельный GitHub падает на любой такой попытке.

Настройки (только сервер):

- `NUXT_EXPORT_REPOS` — `inapp=Neverbyyy/amaya-demo-inapp,pages_hub=Neverbyyy/amaya-demo-pages-hub`,
  можно `@ветка`; без неё — основная ветка репозитория. Из браузера репозиторий не выбрать и не подменить.
- `NUXT_GITHUB_TOKEN` — fine-grained токен **только на эти репозитории**: Contents и Pull requests на запись.

Сейчас это свои демо-репозитории с копией файлов локалей: в рабочие InApp и Pages Hub по ТЗ ничего
не отправляем. Для настоящих проектов меняются только эти две переменные.

### Статус PR без переоткрытия окна — вебхук GitHub

PR смержили или закрыли на GitHub — открытое окно «Выгрузка в код» обновляется само за долю секунды:
«PR #7 смержен — открыть на GitHub», кнопка снова «Создать PR», «В репозитории всё актуально».

```
GitHub (pull_request) → POST /api/github/webhook (подпись X-Hub-Signature-256)
  → PR из ветки amaya-hub/<набор> своего репозитория → Supabase Realtime, канал export-pr, событие { set }
  → открытое окно тихо перечитывает наборы и предпросмотр этого набора
```

Канал публичный, поэтому в событии только имя набора — статус окно всегда спрашивает у сервера
(`lastPr` в `/api/export/sets` — что стало с PR последней выгрузки). Без вебхука (локально или пока не настроен)
окно перечитывает статус при возврате на вкладку. Таблиц и миграций для этого нет.

Настройка:

1. `NUXT_GITHUB_WEBHOOK_SECRET` — случайная строка, в `.env` и в Vercel.
2. В каждом репозитории из `NUXT_EXPORT_REPOS`: Settings → Webhooks → Add webhook —
   Payload URL `https://central-hub-sigma.vercel.app/api/github/webhook`, Content type `application/json`,
   Secret — тот же, «Let me select individual events» → только **Pull requests**. GitHub сразу пришлёт ping —
   в Recent Deliveries должен быть ответ 200.

Маршрут открыт без пароля сервиса, но без верной подписи отвечает 401. Чужие репозитории, ветки и события
игнорируются (`server/lib/github-webhook.ts`, тесты — `tests/unit/github-webhook.test.ts`).

### CLI `amaya-l10n`

Набор выгрузки (`export_sets`) описывает, какие ключи и языки кладутся в какие файлы проекта.
Сейчас два набора: `inapp` → `src/locales/{lang}.json` и `pages_hub` → `i18n/locales/{lang}.json`, 9 языков.
В них идут старые строки проекта (`legacy.inapp.` / `legacy.pages_hub.`) и новые ключи:
у InApp — `common. app. brand. ds. test.`, у Pages Hub — `common. web. brand. ds. test.`.
Служебные ключи автотестов (`common.selftest.`) не выгружаются никогда.
Остальные файлы проектов (у InApp — `ja`, `zh`, `src/locales/new/*`) CLI не читает и не трогает.

В корне проекта — `amaya-l10n.json`, токен — переменная `AMAYA_L10N_TOKEN` (на сервере это `NUXT_CLI_TOKEN`):

```json
{ "hub": "https://central-hub-sigma.vercel.app", "set": "inapp" }
```

```bash
node packages/l10n-cli/amaya-l10n.mjs pull    # забрать файлы и показать, что изменилось по языкам
node packages/l10n-cli/amaya-l10n.mjs diff    # то же без записи; код 1, если есть разница
node packages/l10n-cli/amaya-l10n.mjs check   # файлы не правили руками после pull; код 1, если правили
node packages/l10n-cli/amaya-l10n.mjs import  # занести текущие файлы проекта как есть (legacy.<проект>.)
```

CLI — один файл без зависимостей (Node.js 18+), его можно запускать из любого проекта (`--cwd <папка>`).

**Как устроена выгрузка.** Импорт сохраняет каждый файл шаблоном, а выгрузка меняет в шаблоне только
изменившиеся строки (`packages/l10n-core/src/locale-file.ts`). Без правок файл совпадает с исходным байт в байт —
с пустыми строками, порядком ключей и ручным форматированием, — а `pull` даёт в проекте diff ровно
по изменённым строкам. Это проверяют `packages/l10n-core/test/locale-file.test.ts` на копиях из
`fixtures/legacy/` и `tests/db/legacy.test.ts` на настоящей базе. Если новый ключ совпадает со старым,
выгрузка падает с ошибкой, а не перезаписывает молча.
