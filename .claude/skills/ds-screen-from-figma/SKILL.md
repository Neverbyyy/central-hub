# Экран по фрейму Figma

Цель — экран из готовых деталей, а не вёрстка с нуля. Если деталь не находится — это сигнал дописать дизайн-систему
(отдельно и осознанно), а не сделать её в папке экрана.

## 1. Прочитать фрейм (REST, не MCP — у MCP 6 вызовов в месяц)

```
node tools/figma/node.mjs "<ссылка на фрейм с node-id>"          # дерево: размеры, автолейаут, тексты, цвета
node tools/figma/export.mjs "<ссылка>" <scratchpad>/figma render <id кадров>   # PNG-эталон каждого размера
node tools/figma/export.mjs "<ссылка>" <scratchpad>/figma fills <id кадра>     # исходники картинок
```

Посмотри эталоны всех размеров (667×375, 844×390, 1024×768 — пейволлы; 375, 768 — лендинги) и все шаги.

## 2. Разложить фрейм на детали

Открой `packages/ui/manifest.md`. Для каждого элемента фрейма найди компонент (Ds*), шаблон (Pw*) или блок (Lk*):
кнопка → `DsButton`, заголовок → `DsText`/`DsGameTitle`, тарифы → `DsPlanPicker`, документы внизу → `DsLegalLinks`,
крестик → `DsCloseButton`, картинка → `DsImage`, не помещается по высоте → `DsFit`, и т. д.
Компонент в Figma называется как в коде без префикса (`PlanCard` ↔ `DsPlanCard`).

- Целый экран похож на шаблон (`PwPlusSplit`, `PwHeroSlider`, `LkPage`) — бери шаблон и конфиг.
- Цвет, размер, отступ — найди токен (`packages/tokens/src`, страница «Токены» в Storybook). Значение есть в макете,
  а токена нет — добавь токен в base/тему (значение из Figma), не пиши hex и px.
- Детали нет — скилл `ds-new-component` (компонент в `packages/ui`), а не разметка в экране.

## 3. Тексты

Все надписи — ключи сервиса: скилл `ds-add-strings` (сначала похожие строки — многие уже есть в `common.*`).
Капс в макете — регистр темы (`case.*`), текст в сервисе — обычный. Ручные переносы строк из макета не переносим
(в строках нет HTML, а на других языках переносы свои): заголовкам — класс `ds:text-balance`, строки выравниваются сами.

## 4. Арт

Сначала проверь `packages/art`: общий арт игры не копируется. Размер, который повторяет меньший, не храним: `DsImage` возьмёт
меньший. Лендингу PNG не нужен: `png=no`. Картинки — в папку экрана `art/` по конвенции `<имя>-{small,medium,large}{,@2x}.{png,webp}`.
Ширина каждого размера — сколько картинка занимает на экране в макете 667, 844 и 1024 (у лендинга small — телефон,
wide — от 640):

```
node tools/figma/image-set.mjs <исходник.png> <папка экрана>/art/<имя> small=422 medium=422 large=512 [crop=x,y,w,h]
```

- Исходник: `render` узла с картинкой (кадр «img» целиком — сохраняет фон и градиент под артом) или `fills`
  (исходная картинка без фона — когда фон рисует сам экран).
- Кадрирование на размерах разное (667, 844 и 1024 обрезаны по-своему) — запусти нарезку на каждый размер отдельно,
  с исходником этого размера: `… small=333`, потом `… medium=422`, потом `… large=512`.
- Фон под артом из макета (градиент, цвет) без токена — оставь в картинке (render), а не пиши hex.

Подключение:
`imageSetFromFiles(import.meta.glob('./art/*.{png,webp}', { query: '?url', import: 'default', eager: true }), './art/имя')`.

## 5. Собрать

- Пейволл/онбординг — скилл `ds-new-paywall` (папка варианта в `apps/inapp-preview`).
- Лендинг — скилл `ds-new-landing`.

## 6. Проверить

Скилл `ds-self-check`: линтер (тексты, `ds:`, токены, `<img>`), типы, история в Storybook, скриншоты всех размеров
(`node tools/shot.mjs "<адрес истории iframe.html?id=…>" <папка> 667x375 844x390 1024x768`) рядом с эталоном из шага 1.
Расхождения — исправить; что не решилось дизайн-системой — перечислить в отчёте.
