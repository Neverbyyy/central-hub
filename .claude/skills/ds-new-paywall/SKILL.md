# Новый пейволл или онбординг

Новый пейволл — конфиг, а не тысяча строк копипасты. Экраны другой игры — это тема, тексты, картинки и конфиг.

1. **Шаблон.** Подходит существующий (`PwPlusSplit`: арт/слайды слева + тарифы справа; `PwHeroSlider`: карточка +
   попап + карусель) — экран = `index.vue` с шаблоном и `config.ts` (типы — `packages/paywall-kit/src/config.ts`).
   Не подходит — экран из компонентов Ds* с `usePaywall` (готовность, покупка, повторное открытие) по образцу шаблона.
2. **Папка** `apps/inapp-preview/src/variants/ios/as/<игра>/ds1/<экран>/` — как вариант InApp: `index.vue` (пропсы
   `ScreenProps`: `env`, `theme?`, `forcePurchasing?`), `config.ts`, `presets.ts`, `art/`. Общее для игры — `<игра>/ds1/common/`.
3. **Продукты** — ID как в InApp, по сегментам (`t1`, `u`, `ut1`, `wout1` — из имени варианта). Цены — строки стора
   из данных приложения; «в неделю» и скидки — `@amaya/pricing`.
4. **Тексты** — ключи (`ds-add-strings`): общие тарифы/кнопки — `common.*`, своё — `app.<игра>.<экран>.*`.
5. **Арт** — сначала `packages/art`: что уже есть у игры, не копируется; размер, который повторяет меньший, не нужен. Остальное
   — в `art/` по конвенции, «готов» экран сообщает только после арта, шрифта и цен (это делает `usePaywall`).
6. **Регистрация** — `apps/inapp-preview/src/variants/index.ts` (`id` варианта, `match`, ленивые `load` и `presets`).
7. **История** — `apps/inapp-preview/src/stories/<Экран>.stories.ts` через `screenStory` и `SCREENS_META`
   (пресеты, итог покупки и лог — в панели), порядок — `storySort` раздела «Пейволлы». Файл историй — один на игру:
   мета `Пейволлы/<Игра>` с `id`, по истории на экран. Один экран — имя истории = `<Игра>` (строка в боковой панели);
   второй — новая история в тот же файл, у первой имя меняется на название экрана (игра — выпадающий список, как
   Cars 2 и Farm: On start / On click). Адрес истории — от `id` меты и имени экспорта: от подписей он не зависит.
8. **Сценарии из ТЗ**: тариф выбран при открытии, крестик с задержкой, покупка блокирует экран и двойной тап — одна
   покупка, отмена/ошибка возвращают к выбору, повторное открытие — экран как новый, нет продукта — экран не
   показывается, немецкий не ломает, 667×375 / 844×390 / iPad.
9. **iPhone Duo и safe area**: фон и арт — на весь экран, всё, что нажимается, — в safe area, в любой позе. Крестик и документы —
   в рамке `ds:absolute ds:inset-safe` (с `ds:pointer-events-none`, у детей `ds:pointer-events-auto`; в углу — ещё `ds:m-safe-corner`, запас от скругления экрана), колонка с кнопками — с
   `ds:pt-safe`/`ds:pr-safe`/`ds:pb-safe` снаружи `DsFit`: отступы внутри него уменьшились бы вместе с содержимым. Смотреть в
   эмуляторе все позы Duo: сценарии ловят только рамки, а срезанный арт видно лишь глазами.
10. **Эмулятор и сценарии**: метки `data-pw="cta"` на главной кнопке и `data-pw="close"` на крестике; экран — в `SCREENS`
   скрипта `apps/inapp-preview/scripts/scenarios.mjs` (что блокируется на время покупки, как поменять выбор);
   `pnpm --filter @amaya/inapp-preview scenarios --only <экран>` — без FAIL. Лог эмулятора (`dev`, корень) — без
   подсвеченных строк.
10. **Проверка**: `ds-self-check`.

## Онбординг

Устроен так же, со своими отличиями:

- Папка — `<игра>/ds1/onboarding/` (несколько онбордингов — `onboarding-<имя>`), вариант — `ios_as_<игра>_ds1_varb_<сегмент>_onboarding_v1`.
- Шаблона Pw* для онбординга пока нет: экран из Ds* (`DsRoot`, `DsImage`, `DsText`, `DsButton`, `DsLegalLinks`,
  `DsCloseButton`, `DsFit`) и `usePaywall` — «готов» после арта всех шагов и шрифта, повторное открытие — с шага 1.
- Продуктов нет — один пресет `default`. Шаги листает главная кнопка; переход — opacity/transform, тексты шагов в одной
  ячейке сетки, чтобы ничего не прыгало. Двойной тап не должен проскочить шаг (`useTapGuard` у кнопки).
- Конец онбординга — `env.close()`: отдельной команды «онбординг пройден» в `PaywallEnv` пока нет (вопрос к продукту).
- Тексты — `app.<игра>.onboarding.step_<N>.*`; одинаковые для нескольких игр — `common.onboarding.*`.
- История — раздел «Онбординги» (`Онбординги/<Игра>`), `screenStory` с одним пресетом.
