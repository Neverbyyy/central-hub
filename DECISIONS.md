## 28 октября — этап 1, день 1

- Структура монорепо из этапа 2 (`apps/central-hub`, `packages/*`) заведена сразу, чтобы не переезжать через неделю; Turborepo добавлю на этапе 2.
- Правила ключей проверяются дважды: в `packages/l10n-core` (подсказки в UI, CLI, MCP) и в базе (`l10n_key_error` + триггеры) — обойти базу нельзя ни одним клиентом.
- Переводы остаются в `localizations.translations` (jsonb), как в прототипе: грид, realtime и атомарный `set_translation` продолжают работать, а на нескольких тысячах строк нормализация в отдельную таблицу ничего не даёт.
- «Устарело после правки английского» — через счётчик: `source_rev` растёт при правке исходного языка, перевод помнит `based_on`; меньше — устарел.
- Пустое значение ячейки убирает перевод из `translations`, а не хранит `""`: в выгрузку не попадут пустые кнопки.
- Автор и источник правки передаются параметрами функций записи и через `set_config('hub.*')` доходят до триггера истории — историю нельзя пропустить ни одним путём записи.
- Удаление строк и изменение истории запрещены триггерами — даже для серверного ключа; «удалить» в интерфейсе = пометить устаревшим, с кнопкой «Вернуть» в тосте вместо `confirm()`.
- Переименование ключей пока запрещено триггером: в ТЗ его нет, а MCP переименовывать нельзя.
- Конфликт «ключ — начало другого ключа» проверяется только среди новых ключей; для `legacy.*` его проверит импорт по точному пути из файла (день 2).
- `null` в переводе допустим только у `legacy.*`: так он лежит в исходном `uz.json` InApp, и выгрузка должна совпасть.
- Миграция `lockdown` отбирает права и на будущие объекты (`alter default privileges`), а `security_audit()` + тест сверяют все права `anon`/`authenticated` с белым списком — новая функция с открытыми правами уронит тест.
- Роль `authenticated` закрыта так же, как `anon`, а регистрация в Supabase Auth выключена: Supabase Auth сервисом не используется.
- Сессия — зашифрованная cookie на `useSession` из h3 (без новых библиотек); вход через Google потом заменит только `server/utils/session.ts` и `login`.
- Пароль сравнивается по SHA-256 через `timingSafeEqual`, неверный пароль отвечает с паузой 500 мс — замедляет перебор без хранилища попыток.
- Пререндер главной убран: статический HTML отдавался бы в обход пароля.
- Языки, коды игр и сайтов лежат в миграции, а не в seed: без них сервис не работает, и `db push` в новую базу должен приносить их сам.
- Тесты базы пишут в служебный ключ `common.selftest.anchor.default` и оставляют его помеченным устаревшим — удалить строку нельзя никому. Пока боевых данных нет, тесты идут против основной базы; к дню 3 CI переедет на локальный Supabase.
- Превью Vercel пока смотрят в ту же базу, что и основной стенд: второй проект Supabase для превью — когда появятся настоящие данные.
- Страницы прототипа `/ab-tests` и `/audit-page` оставлены как есть (решение владельца): `/ab-tests` писал в базу напрямую и после закрытия прав сохранять не может, его фильтр по тегам смотрит в удалённую колонку `attributes`.

## 28 октября — этап 1, день 1

- В сервисе только 9 языков по ТЗ (решение владельца). Остальные 34 файла InApp (`ja`, `zh` и `src/locales/new/*`) остаются в InApp и правятся руками: импорт их не читает, а выгрузка и CLI их никогда не пишут и не удаляют.
- Выгрузка правит исходный файл как шаблон, а не собирает его заново: файлы InApp отформатированы руками (около 140 пустых строк на файл, пробелы в конце строк, свой порядок ключей в `ru` и `sv`, дубль ключа), и `JSON.stringify` их не воспроизводит. Так выгрузка без правок совпадает с файлом байт в байт, а `pull` меняет в проекте только изменённые строки.
- Ключ legacy-строки — префикс + путь через точку, а точный путь хранится в `legacy_path`: 14 ключей InApp содержат точку прямо в имени, и без пути их не отличить от раздела.
- Импортированные строки получают статус «утверждён»: они уже в продакшене. Повторный импорт тех же файлов ничего не меняет, а ключи, пропавшие из файлов, помечает устаревшими (не удаляет).
- Дубль `letter_reset_password_button` в InApp сервис хранит так же, как его видит vue-i18n, — второе значение; первое остаётся в шаблоне нетронутым, пока ключ не правят.
- Копии файлов для автотестов сняты из коммитов (`git show`), а не из рабочей копии, и помечены `-text` в `.gitattributes` — иначе Git на Windows подменит переводы строк и побайтные тесты сломаются у других.
- CLI — один `.mjs` без зависимостей на Node 18+: его можно запустить из любого проекта, включая InApp на старом Node; свой токен (`AMAYA_L10N_TOKEN` / `NUXT_CLI_TOKEN`), отдельный от будущих токенов MCP и Figma.
- CLI сравнивает файлы без учёта CRLF/LF и пишет в том стиле переводов строк, который уже был в файле: рабочие копии на Windows с `autocrlf` иначе давали бы ложную разницу во всех файлах.
- `check` работает без сети — по хешам из `.amaya-l10n.lock`, чтобы его можно было ставить в CI проекта.
- Ошибка lockdown: новые функции получали `EXECUTE` для `PUBLIC` (а значит и `anon`) — в Postgres это глобальное значение по умолчанию, и `ALTER DEFAULT PRIVILEGES … IN SCHEMA` его не отзывает. Исправлено глобальным отзывом в отдельной миграции; нашёл автотест прав.

## 29 октября — этап 1, день 2

- Статусы новых текстов: из интерфейса — «черновик» (`draft`), от нейросети — «от ИИ» (`ai`); утверждение (`approved`) — позже, как в ТЗ.
- Нейросеть не может перезаписать текст человека: запрет в самой базе (`set_ai_translation` меняет только пустой перевод или прежний черновик ИИ), а не только в инструментах MCP.
- Похожие строки — `pg_trgm` по английскому тексту и по имени ключа (у legacy — без префикса проекта). В интерфейсе их показываем всегда; в MCP при совпадении от 60 % ключ не создаётся без `not_duplicate_reason` — дубль должен быть осознанным.
- MCP — Streamable HTTP без сессий и с JSON-ответами: на каждый запрос новый сервер и транспорт, поэтому работает на Vercel без общего состояния. Ошибки `/mcp` отдаются готовым `Response`, без страницы ошибки Nuxt.
- Свой токен MCP (`NUXT_MCP_TOKEN` / `AMAYA_HUB_TOKEN`), отдельный от токена CLI: у нейросети и сборки разные права и разный срок жизни.
- Новые ключи выгружаются в проекты по префиксам набора: InApp — `common. app. brand. ds. test.`, Pages Hub — `common. web. brand. ds. test.`. Служебные `common.selftest.` исключены (`exclude_prefixes`) — тесты базы не могут попасть в файлы проектов.
- Автотест выгрузки сверяет байт в байт только строки проекта (`legacy`), а для полной выгрузки проверяет, что старые строки не изменились и добавлены только новые ключи: в базе живут настоящие новые ключи.
- «Человек не представился» — 403 `Name Required`, а не 409: 409 остаётся честным конфликтом («ключ уже есть»), и форма показывает ошибку вместо перехода на вход.
- MCP SDK принёс вторую версию `cookie`, и Vite в dev перестал предсобирать ту, что импортирует `@supabase/ssr` — страницы не монтировались. В `optimizeDeps` указан точный путь `@nuxtjs/supabase > @supabase/ssr > cookie`.
- Первый настоящий ключ по новой схеме — `common.button.continue.default` — создал Claude Code через MCP при сквозной проверке: он пригодится в дизайн-системе.

### Редактор

- «Устарел» и набор статусов строки — вычисляемые колонки базы (`stale_langs`, `status_values`) с GIN-индексами: PostgREST не умеет сравнивать две колонки (`based_on` с `source_rev`) и искать по значениям JSON, а фильтры грида идут из браузера публичным ключом.
- Защита от одновременной правки — сравнение с ожидаемым значением, а не блокировки: интерфейс передаёт `expected` (текст ячейки на момент начала правки), и `set_translation` при расхождении бросает свою ошибку `HB409` с текущим текстом и автором. Без `expected` (MCP, импорт, тесты) поведение прежнее. Отмена (Ctrl+Z) передаёт как `expected` свой же текст — чужую более свежую правку она не перезапишет.
- Утверждение ставит `based_on = source_rev`, то есть снимает «устарел»: человек подтвердил, что перевод верен для текущего английского. В очереди Enter без правок у устаревшего перевода делает то же самое.
- `t('…')` у legacy-строк копируется по `legacy_path` (`t('basic.task_1')`), а не по ключу сервиса (`legacy.inapp.basic.task_1`): код InApp и Pages Hub зовёт строки по старым путям.
- Панель ключа не модальная: грид остаётся под клавиатурой, панель идёт за активной строкой. Ключ панели — в адресе (`?key=`), чтобы ссылку и ⌘K можно было открыть сразу на нужном ключе; при движении стрелками адрес обновляется с паузой.
- Палитра ⌘K ищет ключи в базе (`search_text`), а не среди загруженных в грид строк: в гриде подгружены только видимые страницы.
- Правила нового ключа (имя по схеме, `legacy.*` только импортом, описание от 10 символов) — в `l10n-core` (`newKeyError`, `descriptionError`): форма и сервер проверяют одним кодом. Кнопка «Создать ключ» не выключается молча — рядом написано, чего не хватает.
- «Устаревший» в интерфейсе означал две вещи, и фильтр путали. Теперь: «Перевод устарел» — английский поменяли после перевода (один язык), «Ключ устарел» — ключ помечен устаревшим, выведен из употребления (весь ключ); кнопки стоят рядом. У вторых своя выборка `?deprecated=1`: таблица в ней только для чтения, выделенные ключи можно вернуть.

## 29 октября — этап 1: тесты, бэкапы, свойства ключа, Figma

- Тесты базы переехали на одноразовый локальный Supabase (Docker), как и обещано выше. Причина стала острой: тест импорта при каждом прогоне заново импортировал копии файлов в основную базу, а `import_legacy` заменяет переводы legacy-строк значениями из файлов — правки людей в строках InApp и Pages Hub откатились бы. По истории ничего не потеряно (0 перезаписей). Теперь `test:db` отказывается работать не с `127.0.0.1`, строки из fixtures заносит общий `globalSetup`.
- Права настоящего стенда проверяет отдельный `pnpm test:stand` (только `security.test.ts` против `.env`): он лишь пытается писать публичным ключом и ждёт отказа, основной базе не вредит.
- CI — GitHub Actions на каждый push и PR: unit-тесты и тесты базы на свежем локальном Supabase, без секретов. Lint и typecheck в CI не включены: в страницах прототипа (`/ab-tests`, `RiveKeyboard`, `tags`), которые решено не трогать, уже есть ошибки; сборку на каждый push делает Vercel.
- Ежедневный дамп — артефакты GitHub Actions на 30 дней (решение владельца): не растит историю git и виден только участникам приватного репо. Подключение — через Session pooler: прямой адрес базы Supabase только IPv6, раннеры GitHub его не умеют. Секрет — только пароль базы, адрес собирает workflow: первые попытки вставить строку подключения целиком в секрет сорвались (в него попадали шаблон или чужое значение), а адрес с идентификатором проекта и регионом не секретный. Восстановление проверено: ключи и переводы из дампа совпали с основной базой до байта.
- Свойства ключа (описание, теги, лимит, ссылка на Figma) правятся в панели по правилу «последний побеждает», без сверки `expected`, как у текстов: одновременная правка описания редка, а история покажет обе. Устаревший ключ не правится, у строк InApp и Pages Hub описание можно оставить пустым.
- Figma: имя переменной — ключ с `/` вместо точек, и для строк InApp и Pages Hub тоже: точка внутри части их пути означает вложенность (`settings` → `auth.continue`). На всех 2727 ключах это не дало ни одного совпадения имён; совпадение всё равно ловится и останавливает выгрузку.
- Формат для Figma — встроенный импорт переменных (W3C Design Tokens), а не формат прототипа: его не читает ни сам Figma, ни плагин с похожей структурой (Figma Variables Generator работает только с цветами). Файл на каждый язык, потому что Figma делает из каждого импортированного файла режим; каждый ключ есть в каждом файле, потому что переменная создаётся, только если она нашлась во всех файлах. Ключи вложены группами — Figma сама превращает их в имена через `/`. Плагин не нужен; если Антон работает через свой, меняется одна функция `figmaModeFiles`.
- Фоновая задача `nuxt dev` на Windows при остановке оставляла процесс node, и к вечеру их было 11 — проверка, рассчитанная на локальную базу, попала в старый сервер с основной. Записи не было (новой функции там ещё не существовало), но браузерные проверки теперь первым делом сверяют адрес базы и останавливаются, если он не тот.

## 29 октября — этап 1: плагин Figma

- Тексты в Figma — свой плагин «Amaya Hub — локализация», а не таблица и не ZIP. Антон загружал тексты плагином «Sheets <> Variables» из публичной Google-таблицы; встроенный импорт Figma обновляет существующие переменные только по одному режиму, а REST API для записи переменных есть только на Enterprise. Плагин берёт тексты прямо из сервиса — таблица и ручной перенос уходят, тексты правятся только в сервисе. ТЗ разрешает свой плагин, «если останется время»: этап 1 идёт с запасом. ZIP для встроенного импорта остался запасным путём.
- Токен плагина — отдельный `NUXT_FIGMA_TOKEN`, только чтение; дизайнер вставляет его в плагин сам (решение владельца), плагин хранит его в `figma.clientStorage`. Архив плагина скачивается из сервиса за паролем, токена в нём нет, а адрес сервиса вписывается при скачивании — плагин со стенда, превью и localhost ходит каждый в свой сервис.
- Живое обновление — опрос раз в 5 с: «что изменилось с прошлого ответа» по `updated_at` с запасом 30 с, а не Supabase Realtime. В плагин не нужно тащить supabase-js и публичный ключ, доступ только по токену плагина; запас ловит строки, закоммиченные позже начала транзакции, и расхождение часов, а плагин всё равно пишет только отличия. Без открытого плагина Figma ничего не обновит — для этого команда «Обновить тексты» без окна (её повторяет Ctrl+Alt+P) и кнопка в правой панели файла.
- Переменная находится по ключу (pluginData), затем по имени, и значения пишутся только там, где отличаются: переменные не пересоздаются, привязки слоёв переживают любое обновление. Плагин ничего не удаляет — лишние и помеченные устаревшими показывает списком: удаление отвязало бы слои.
- Режимы называются по-английски (English, Russian…), как у Антона сейчас, служебная переменная `language` с названием режима — тоже его приём. Нет перевода — пустая строка, как в ZIP (решение владельца).
- Плагин — чистый JS без сборки и зависимостей, как CLI, синтаксис не новее ES2017: песочница основного потока Figma отставала от браузеров. Проверяется тестом на поддельном `figma` в `node:vm` и сквозной проверкой с настоящим сервером; в настоящей Figma — руками.
- `central-hub` объявляет `@amaya/figma-plugin` своей зависимостью, хотя берёт его файлы по пути (`nitro.serverAssets`): Vercel пропускает деплой коммитов, которые не трогают Root Directory и его workspace-зависимости, и правки только плагина на стенд не уезжали.
- Маршруты плагина названы без метода (`texts.ts`, а не `texts.get.ts`): иначе preflight `OPTIONS` не доходил до обработчика и уходил в рендер страниц с редиректом на вход. Ошибки плагину отдаются JSON с заголовками CORS — иначе он видел бы сбой сети вместо «неверный токен».

## 29 октября — этап 1: выгрузка в проекты кнопкой, только утверждённое

- В проекты уходят только утверждённые тексты (решение владельца). Сам по себе статус не помогает: правка ставит «черновик», и прежнего утверждённого текста больше нигде нет — строка пропала бы из файла, и InApp показал бы английский. Поэтому база хранит у каждого языка последний утверждённый текст (`approved`), и выгрузка — кнопка и CLI одинаково — берёт его. Новый ключ попадает в файлы после утверждения.
- `approved` считает триггер из статусов: язык утверждён — снимок текущего текста. Одно правило покрывает утверждение, импорт и создание ключа сразу утверждённым, а напрямую колонку не переписать. Существующие строки заполнены по истории: последнее «статус → утверждён» или импорт — так тестовые правки в основной базе (`ADSывыв`, `СКАЧАТЬйцйцйц`) в выгрузку не попадут.
- Ключи нейросети попадают в проект только после утверждения человеком. Это меняет сценарий ТЗ «MCP создаёт ключ → `pull` кладёт его в проект»: между ними теперь утверждение. ТЗ говорит «утверждать будем позже» — отметить для Кирилла.
- Figma не меняется: плагин и ZIP показывают и черновики — дизайнеру нужны тексты до утверждения.
- Кнопка «Выгрузить в код» открывает PR, а не коммитит в основную ветку (решение владельца): мержит человек, как с GitHub-интеграциями Crowdin и Lokalise. Своя ветка `amaya-hub/<набор>` каждый раз пересобирается от основной, поэтому PR один и после мержа содержит только новое; выгружать нечего — свой PR закрывается.
- Сервис пишет только в свою ветку и PR: не в основную ветку, без мержа и удалений. Защиту веток на GitHub для приватных репозиториев на бесплатном тарифе не включить, поэтому это держит код и проверяет тест на поддельном GitHub. Токен — fine-grained только на демо-репозитории.
- Репозитории наборов — в окружении (`NUXT_EXPORT_REPOS`), а не в базе: пара «репозиторий + токен» зависит от стенда, и браузер её не подменит. Для настоящих проектов меняются только две переменные.

## 30 октября — этап 1: подсказки при создании ключа

- Ключ вводится в одном поле с подсказками к следующей части, а не конструктором по шагам (решение владельца): с клавиатуры быстрее, ключ можно вставить целиком, а новичку список под полем показывает, что можно дальше. Подсказки — из того, что уже есть: начала из «Как называть ключи», коды из справочника, разделы из дерева; типичные разделы (`paywall`, `onboarding`, `banner`) — только пока своих нет.

- Список подсказок — свой, а не `UInputMenu`: нужно дописывать часть ключа и продолжать печатать, а не выбирать готовое значение. Разметка по образцу ARIA combobox; Esc закрывает список, а не всю панель.
- `newKeyError` сначала проверяет начало: «legacy» без продолжения — объяснение про импорт, а не «слишком короткий ключ»; в списке допустимых начал для нового ключа больше нет `legacy.`. Сообщение одинаковое в форме, API и MCP.
- Устаревший ключ не занимает имя (миграция `20261030100000_deprecated_frees_name`): «ключ не может быть началом другого» проверяется только среди действующих ключей. Правило нужно, чтобы в JSON раздел не был одновременно строкой, а устаревшие в выгрузку, Figma и ZIP не попадают. Иначе одна пробная строка (`app.farm.banner`) навсегда запрещала бы раздел с тем же именем: удалять и переименовывать ключи нельзя. Обратная сторона — устаревший ключ не вернуть, пока его место занято: база отвечает «не вернуть: его место занял …».
- В форме «Новый ключ» только ключ, описание и теги (решение владельца): текст EN вписывают потом в гриде или через MCP, лимит длины — в панели ключа. ТЗ текст при создании не требует; `POST /api/keys` принимает `en` по-прежнему, но необязательно. Описание оставлено обязательным, как в ТЗ, — в форме, на сервере, в MCP и в базе (решение владельца).
- Куда уйдёт ключ, видно в интерфейсе: у начал в подсказках «Новый ключ» (`app.` — InApp, `web.` — Pages Hub, `common.` — оба), строкой под полем ключа и в панели ключа. Правило «ключ входит в набор» вынесено в `keyInExportSet` (l10n-core) — им же фильтрует серверная выгрузка, поэтому подсказка не разойдётся с тем, что попадёт в PR. Наборы для подсказок — отдельным лёгким `GET /api/export/rules`: `/api/export/sets` ходит в GitHub и для формы и панели тяжёл.

## 31 октября — статус PR по вебхуку GitHub

- Окно «Выгрузка в код» узнаёт о мерже по вебхуку GitHub, а не опросом (решение владельца). Цена — настройка вебхука в каждом репозитории: для демо — сами, для настоящих InApp и Pages Hub — их админы или вебхук / GitHub App организации. Без вебхука окно всё равно перечитывает статус при возврате на вкладку — локально и пока вебхук не настроен.
- Без таблицы и миграции: вебхук рассылает событие через Supabase Realtime broadcast (`channel.httpSend`, серверный ключ), а «смержен ли последний PR» сервер спрашивает у GitHub при чтении наборов (`findPr`, `lastPr`). Канал публичный — подделать событие может любой с публичным ключом, поэтому в нём только имя набора, и окно в ответ лишь перечитывает статус с сервера.
- Маршрут `/api/github/webhook` открыт без пароля сервиса и защищён подписью `X-Hub-Signature-256` (HMAC секретом `NUXT_GITHUB_WEBHOOK_SECRET`, сравнение за постоянное время); без секрета на сервере — 503. Учитываются только PR из своей ветки `amaya-hub/<набор>` в репозитории этого набора, не из форка; рассылка не дошла — в лог, GitHub получает 200.
- Окно перечитывает «тихо»: старые данные на месте до ответа, без скелетонов; ошибка тихого обновления не заменяет карточку.
- Выгрузку кнопкой сервис объявляет в тот же канал Realtime сам (`notifyExportChanged` после `/api/export/<набор>/push`): окна коллег обновляются сразу и без вебхука, в том числе локально. Вебхук GitHub остаётся для того, что происходит вне сервиса, — мерж и закрытие PR.
- Строка статуса в карточке строится из данных сервера (`lastRun` + `lastPr`), а не из памяти окна о последнем нажатии: у всех одинаковая «PR #11 обновлён · дата · кто». Мерж или закрытие на GitHub важнее строки выгрузки; если PR закрыл сам сервис («выгружать нечего»), показывается строка выгрузки — она объясняет причину.
- Открытые PR видно без открытия окна — бадж с числом в углу кнопки «Выгрузить в код» (`position: absolute` поверх края, чтобы ширина кнопки не менялась, когда PR открыли или смержили), подсказка — какие и кто выгрузил (решение владельца; уведомления всем и строку в шапке не делали — шумно и тесно). Данные — отдельный лёгкий `/api/export/open-prs` (только открытый PR и строка журнала), а не `/api/export/sets` с подсчётом ждущих утверждения. Обновляется по тому же каналу Realtime и при возврате на вкладку.
- Бадж приходит в HTML страницы: последний ответ `/api/export/open-prs` хранится в куке `hub-open-prs`, и сервер рисует бадж по ней. Иначе он появлялся бы только после загрузки страницы и ответа GitHub (0,3–0,7 с). Не localStorage — его сервер не видит, и бадж всё равно появлялся бы после загрузки скриптов. Не запрос к GitHub при отрисовке — он задержал бы всю страницу. Цена — если PR смержили, пока вкладки не было, старый бадж держится до свежего ответа (меньше секунды).
- Подписка на канал `export-pr` одна на вкладку (`useExportPrEvents`): `supabase.channel()` для той же темы возвращает тот же канал, и две независимые подписки (бадж и окно) мешали бы друг другу — повторный `subscribe()` и отписка окна сняли бы подписку баджа.

  1. Размеры iPad (`large`) — только на экране от 1024 px в ширину **и** от 600 px в высоту: токены, `IMAGE_MEDIA` для арта и вариант `ds:large:` (`@custom-variant` в пресете, у переменной брейкпоинта Tailwind нет высоты). Масштаб считается до первой отрисовки и при изменении размера или содержимого (смена языка). Обёрнуты ряд карточек Cars 2, попап тарифов и правая половина Farm. Не `zoom`: у `transform` одинаковое поведение во всех движках и нет влияния на вёрстку снаружи.

## 3 ноября — Rive

- Рантайм — `@rive-app/webgl2` ровно 2.39.2, как в InApp, а не последний 2.49: анимация в Storybook ведёт себя так же, как потом в продукте. Альтернативы нет — .riv играет только рантайм Rive. В `@amaya/ui` он необязательная peer-зависимость: внутри InApp `DsRive` возьмёт его рантайм и уже прогретый wasm, а не потянет вторую копию.
- wasm (2,6 МБ) — со своего адреса через `configureRive`, а не с unpkg, откуда его по умолчанию берут рантайм и InApp: вебвью без внешней сети или с медленной сетью иначе остаётся без анимации. Запасной `rive_fallback.wasm` — тоже свой; качается, только если основной не поднялся.
- Рантайм грузится динамическим импортом, когда первый `DsRive` подъезжает к экрану (запас 200 px), — страницы без анимации его не качают. За экраном анимация на паузе: сам рантайм останавливается только на скрытой вкладке. Плотность холста — не больше 2x, как у картинок.
- Запуск — следующей микрозадачей после `onLoad`: команды воспроизведения рантайм принимает только после него, а `reset()` внутри `onLoad` в 2.39 уходит в бесконечную рекурсию и вешает страницу (найдено на этом файле, проверено на голой странице).
- Стейт-машина по умолчанию — первая у артборда, как в редакторе Rive. Играет и встаёт только она, по имени: `play()` без имени запустил бы заодно первую анимацию файла, которую рантайм создаёт на паузе.
- Привязка view model — по пропу `bind-view-model`, а не всегда: на запрос view model у артборда без неё wasm пишет ошибку в консоль. В `animation-paywall-cars.riv` лежит пустая `ViewModel1`, ни к чему не привязанная. Просмотр в Storybook сам проверяет артборд и вставляет проп в строку подключения, когда он нужен.
- В Storybook у Rive одна история — просмотр файла; отдельной истории с постером нет (решение пользователя). Проп `poster` у `DsRive` остаётся: ТЗ лендинга требует сначала картинку и картинку на месте анимации, если та не загрузилась.
