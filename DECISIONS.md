# Решения

Одна строка — одно решение, которое я принял сам. Новые — внизу.

## Этап 1, день 1: база, права и вход

- Структура монорепо из этапа 2 (`apps/central-hub`, `packages/*`) заведена сразу, чтобы не переезжать через неделю; Turborepo добавлю на этапе 2.
- Правила ключей проверяются дважды: в `packages/l10n-core` (подсказки в UI, CLI, MCP) и в базе (`l10n_key_error` + триггеры) — обойти базу нельзя ни одним клиентом.
- Переводы остаются в `localizations.translations` (jsonb), как в прототипе: грид, realtime и атомарный `set_translation` продолжают работать, а на нескольких тысячах строк нормализация в отдельную таблицу ничего не даёт.
- «Устарело после правки английского» — через счётчик: `source_rev` растёт при правке исходного языка, перевод помнит `based_on`; меньше — устарел.
- Пустое значение ячейки убирает перевод из `translations`, а не хранит `""`: в выгрузку не попадут пустые кнопки.
- Автор и источник правки передаются параметрами функций записи и через `set_config('hub.*')` доходят до триггера истории — историю нельзя пропустить ни одним путём записи.
- Удаление строк и изменение истории запрещены триггерами — даже для серверного ключа; «удалить» в интерфейсе = пометить устаревшим, с кнопкой «Вернуть» в тосте вместо `confirm()`.
- Переименование ключей пока запрещено триггером: в ТЗ его нет, а MCP переименовывать нельзя.
- Конфликт «ключ — начало другого ключа» проверяется только среди новых ключей; для `legacy.*` его проверит импорт по точному пути из файла (день 2).
- `null` в переводе допустим только у `legacy.*`: так он лежит в исходном `uz.json` InApp, и выгрузка должна совпасть.
- Миграция `lockdown` отбирает права и на будущие объекты (`alter default privileges`), а `security_audit()` + тест сверяют все права `anon`/`authenticated` с белым списком — новая функция с открытыми правами уронит тест.
- Роль `authenticated` закрыта так же, как `anon`, а регистрация в Supabase Auth выключена: Supabase Auth сервисом не используется.
- Сессия — зашифрованная cookie на `useSession` из h3 (без новых библиотек); вход через Google потом заменит только `server/utils/session.ts` и `login`.
- Пароль сравнивается по SHA-256 через `timingSafeEqual`, неверный пароль отвечает с паузой 500 мс — замедляет перебор без хранилища попыток.
- Пререндер главной убран: статический HTML отдавался бы в обход пароля.
- Языки, коды игр и сайтов лежат в миграции, а не в seed: без них сервис не работает, и `db push` в новую базу должен приносить их сам.
- Тесты базы пишут в служебный ключ `common.selftest.anchor.default` и оставляют его помеченным устаревшим — удалить строку нельзя никому. Пока боевых данных нет, тесты идут против основной базы; к дню 3 CI переедет на локальный Supabase.
- Превью Vercel пока смотрят в ту же базу, что и основной стенд: второй проект Supabase для превью — когда появятся настоящие данные.
- Страницы прототипа `/ab-tests` и `/audit-page` оставлены как есть (решение владельца): `/ab-tests` писал в базу напрямую и после закрытия прав сохранять не может, его фильтр по тегам смотрит в удалённую колонку `attributes`.

## Этап 1, день 1: импорт, выгрузка и CLI

- В сервисе только 9 языков по ТЗ (решение владельца). Остальные 34 файла InApp (`ja`, `zh` и `src/locales/new/*`) остаются в InApp и правятся руками: импорт их не читает, а выгрузка и CLI их никогда не пишут и не удаляют.
- Выгрузка правит исходный файл как шаблон, а не собирает его заново: файлы InApp отформатированы руками (около 140 пустых строк на файл, пробелы в конце строк, свой порядок ключей в `ru` и `sv`, дубль ключа), и `JSON.stringify` их не воспроизводит. Так выгрузка без правок совпадает с файлом байт в байт, а `pull` меняет в проекте только изменённые строки.
- Ключ legacy-строки — префикс + путь через точку, а точный путь хранится в `legacy_path`: 14 ключей InApp содержат точку прямо в имени, и без пути их не отличить от раздела.
- Импортированные строки получают статус «утверждён»: они уже в продакшене. Повторный импорт тех же файлов ничего не меняет, а ключи, пропавшие из файлов, помечает устаревшими (не удаляет).
- Дубль `letter_reset_password_button` в InApp сервис хранит так же, как его видит vue-i18n, — второе значение; первое остаётся в шаблоне нетронутым, пока ключ не правят.
- Копии файлов для автотестов сняты из коммитов (`git show`), а не из рабочей копии, и помечены `-text` в `.gitattributes` — иначе Git на Windows подменит переводы строк и побайтные тесты сломаются у других.
- CLI — один `.mjs` без зависимостей на Node 18+: его можно запустить из любого проекта, включая InApp на старом Node; свой токен (`AMAYA_L10N_TOKEN` / `NUXT_CLI_TOKEN`), отдельный от будущих токенов MCP и Figma.
- CLI сравнивает файлы без учёта CRLF/LF и пишет в том стиле переводов строк, который уже был в файле: рабочие копии на Windows с `autocrlf` иначе давали бы ложную разницу во всех файлах.
- `check` работает без сети — по хешам из `.amaya-l10n.lock`, чтобы его можно было ставить в CI проекта.
- Ошибка lockdown: новые функции получали `EXECUTE` для `PUBLIC` (а значит и `anon`) — в Postgres это глобальное значение по умолчанию, и `ALTER DEFAULT PRIVILEGES … IN SCHEMA` его не отзывает. Исправлено глобальным отзывом в отдельной миграции; нашёл автотест прав.

## Этап 1, день 2

- Статусы новых текстов: из интерфейса — «черновик» (`draft`), от нейросети — «от ИИ» (`ai`); утверждение (`approved`) — позже, как в ТЗ.
- Нейросеть не может перезаписать текст человека: запрет в самой базе (`set_ai_translation` меняет только пустой перевод или прежний черновик ИИ), а не только в инструментах MCP.
- Похожие строки — `pg_trgm` по английскому тексту и по имени ключа (у legacy — без префикса проекта). В интерфейсе их показываем всегда; в MCP при совпадении от 60 % ключ не создаётся без `not_duplicate_reason` — дубль должен быть осознанным.
- MCP — Streamable HTTP без сессий и с JSON-ответами: на каждый запрос новый сервер и транспорт, поэтому работает на Vercel без общего состояния. Ошибки `/mcp` отдаются готовым `Response`, без страницы ошибки Nuxt.
- Свой токен MCP (`NUXT_MCP_TOKEN` / `AMAYA_HUB_TOKEN`), отдельный от токена CLI: у нейросети и сборки разные права и разный срок жизни.
- Новые ключи выгружаются в проекты по префиксам набора: InApp — `common. app. brand. ds. test.`, Pages Hub — `common. web. brand. ds. test.`. Служебные `common.selftest.` исключены (`exclude_prefixes`) — тесты базы не могут попасть в файлы проектов.
- Автотест выгрузки сверяет байт в байт только строки проекта (`legacy`), а для полной выгрузки проверяет, что старые строки не изменились и добавлены только новые ключи: в базе живут настоящие новые ключи.
- «Человек не представился» — 403 `Name Required`, а не 409: 409 остаётся честным конфликтом («ключ уже есть»), и форма показывает ошибку вместо перехода на вход.
- MCP SDK принёс вторую версию `cookie`, и Vite в dev перестал предсобирать ту, что импортирует `@supabase/ssr` — страницы не монтировались. В `optimizeDeps` указан точный путь `@nuxtjs/supabase > @supabase/ssr > cookie`.
- Первый настоящий ключ по новой схеме — `common.button.continue.default` — создал Claude Code через MCP при сквозной проверке: он пригодится в дизайн-системе.

### Редактор

- «Устарел» и набор статусов строки — вычисляемые колонки базы (`stale_langs`, `status_values`) с GIN-индексами: PostgREST не умеет сравнивать две колонки (`based_on` с `source_rev`) и искать по значениям JSON, а фильтры грида идут из браузера публичным ключом.
- Защита от одновременной правки — сравнение с ожидаемым значением, а не блокировки: интерфейс передаёт `expected` (текст ячейки на момент начала правки), и `set_translation` при расхождении бросает свою ошибку `HB409` с текущим текстом и автором. Без `expected` (MCP, импорт, тесты) поведение прежнее. Отмена (Ctrl+Z) передаёт как `expected` свой же текст — чужую более свежую правку она не перезапишет.
- Утверждение ставит `based_on = source_rev`, то есть снимает «устарел»: человек подтвердил, что перевод верен для текущего английского. В очереди Enter без правок у устаревшего перевода делает то же самое.
- `t('…')` у legacy-строк копируется по `legacy_path` (`t('basic.task_1')`), а не по ключу сервиса (`legacy.inapp.basic.task_1`): код InApp и Pages Hub зовёт строки по старым путям.
- Панель ключа не модальная: грид остаётся под клавиатурой, панель идёт за активной строкой. Ключ панели — в адресе (`?key=`), чтобы ссылку и ⌘K можно было открыть сразу на нужном ключе; при движении стрелками адрес обновляется с паузой.
- Палитра ⌘K ищет ключи в базе (`search_text`), а не среди загруженных в грид строк: в гриде подгружены только видимые страницы.
- Правила нового ключа (имя по схеме, `legacy.*` только импортом, описание от 10 символов) — в `l10n-core` (`newKeyError`, `descriptionError`): форма и сервер проверяют одним кодом. Кнопка «Создать ключ» не выключается молча — рядом написано, чего не хватает.
- «Устаревший» в интерфейсе означал две вещи, и фильтр путали. Теперь: «Перевод устарел» — английский поменяли после перевода (один язык), «Ключ устарел» — ключ помечен устаревшим, выведен из употребления (весь ключ); кнопки стоят рядом. У вторых своя выборка `?deprecated=1`: таблица в ней только для чтения, выделенные ключи можно вернуть.

## Этап 1: тесты, бэкапы, свойства ключа, Figma

- Тесты базы переехали на одноразовый локальный Supabase (Docker), как и обещано выше. Причина стала острой: тест импорта при каждом прогоне заново импортировал копии файлов в основную базу, а `import_legacy` заменяет переводы legacy-строк значениями из файлов — правки людей в строках InApp и Pages Hub откатились бы. По истории ничего не потеряно (0 перезаписей). Теперь `test:db` отказывается работать не с `127.0.0.1`, строки из fixtures заносит общий `globalSetup`.
- Права настоящего стенда проверяет отдельный `pnpm test:stand` (только `security.test.ts` против `.env`): он лишь пытается писать публичным ключом и ждёт отказа, основной базе не вредит.
- CI — GitHub Actions на каждый push и PR: unit-тесты и тесты базы на свежем локальном Supabase, без секретов. Lint и typecheck в CI не включены: в страницах прототипа (`/ab-tests`, `RiveKeyboard`, `tags`), которые решено не трогать, уже есть ошибки; сборку на каждый push делает Vercel.
- Ежедневный дамп — артефакты GitHub Actions на 30 дней (решение владельца): не растит историю git и виден только участникам приватного репо. Подключение — через Session pooler: прямой адрес базы Supabase только IPv6, раннеры GitHub его не умеют. Секрет — только пароль базы, адрес собирает workflow: первые попытки вставить строку подключения целиком в секрет сорвались (в него попадали шаблон или чужое значение), а адрес с идентификатором проекта и регионом не секретный. Восстановление проверено: ключи и переводы из дампа совпали с основной базой до байта.
- Свойства ключа (описание, теги, лимит, ссылка на Figma) правятся в панели по правилу «последний побеждает», без сверки `expected`, как у текстов: одновременная правка описания редка, а история покажет обе. Устаревший ключ не правится, у строк InApp и Pages Hub описание можно оставить пустым.
- Figma: имя переменной — ключ с `/` вместо точек, и для строк InApp и Pages Hub тоже: точка внутри части их пути означает вложенность (`settings` → `auth.continue`). На всех 2727 ключах это не дало ни одного совпадения имён; совпадение всё равно ловится и останавливает выгрузку.
- Формат для Figma — встроенный импорт переменных (W3C Design Tokens), а не формат прототипа: его не читает ни сам Figma, ни плагин с похожей структурой (Figma Variables Generator работает только с цветами). Файл на каждый язык, потому что Figma делает из каждого импортированного файла режим; каждый ключ есть в каждом файле, потому что переменная создаётся, только если она нашлась во всех файлах. Ключи вложены группами — Figma сама превращает их в имена через `/`. Плагин не нужен; если Антон работает через свой, меняется одна функция `figmaModeFiles`.
- Фоновая задача `nuxt dev` на Windows при остановке оставляла процесс node, и к вечеру их было 11 — проверка, рассчитанная на локальную базу, попала в старый сервер с основной. Записи не было (новой функции там ещё не существовало), но браузерные проверки теперь первым делом сверяют адрес базы и останавливаются, если он не тот.

## Этап 1: плагин Figma

- Тексты в Figma — свой плагин «Amaya Hub — локализация», а не таблица и не ZIP. Антон загружал тексты плагином «Sheets <> Variables» из публичной Google-таблицы; встроенный импорт Figma обновляет существующие переменные только по одному режиму, а REST API для записи переменных есть только на Enterprise. Плагин берёт тексты прямо из сервиса — таблица и ручной перенос уходят, тексты правятся только в сервисе. ТЗ разрешает свой плагин, «если останется время»: этап 1 идёт с запасом. ZIP для встроенного импорта остался запасным путём.
- Токен плагина — отдельный `NUXT_FIGMA_TOKEN`, только чтение; дизайнер вставляет его в плагин сам (решение владельца), плагин хранит его в `figma.clientStorage`. Архив плагина скачивается из сервиса за паролем, токена в нём нет, а адрес сервиса вписывается при скачивании — плагин со стенда, превью и localhost ходит каждый в свой сервис.
- Живое обновление — опрос раз в 5 с: «что изменилось с прошлого ответа» по `updated_at` с запасом 30 с, а не Supabase Realtime. В плагин не нужно тащить supabase-js и публичный ключ, доступ только по токену плагина; запас ловит строки, закоммиченные позже начала транзакции, и расхождение часов, а плагин всё равно пишет только отличия. Без открытого плагина Figma ничего не обновит — для этого команда «Обновить тексты» без окна (её повторяет Ctrl+Alt+P) и кнопка в правой панели файла.
- Переменная находится по ключу (pluginData), затем по имени, и значения пишутся только там, где отличаются: переменные не пересоздаются, привязки слоёв переживают любое обновление. Плагин ничего не удаляет — лишние и помеченные устаревшими показывает списком: удаление отвязало бы слои.
- Режимы называются по-английски (English, Russian…), как у Антона сейчас, служебная переменная `language` с названием режима — тоже его приём. Нет перевода — пустая строка, как в ZIP (решение владельца).
- Плагин — чистый JS без сборки и зависимостей, как CLI, синтаксис не новее ES2017: песочница основного потока Figma отставала от браузеров. Проверяется тестом на поддельном `figma` в `node:vm` и сквозной проверкой с настоящим сервером; в настоящей Figma — руками.
- `central-hub` объявляет `@amaya/figma-plugin` своей зависимостью, хотя берёт его файлы по пути (`nitro.serverAssets`): Vercel пропускает деплой коммитов, которые не трогают Root Directory и его workspace-зависимости, и правки только плагина на стенд не уезжали.
- Маршруты плагина названы без метода (`texts.ts`, а не `texts.get.ts`): иначе preflight `OPTIONS` не доходил до обработчика и уходил в рендер страниц с редиректом на вход. Ошибки плагину отдаются JSON с заголовками CORS — иначе он видел бы сбой сети вместо «неверный токен».

## Этап 1: выгрузка в проекты кнопкой, только утверждённое

- В проекты уходят только утверждённые тексты (решение владельца). Сам по себе статус не помогает: правка ставит «черновик», и прежнего утверждённого текста больше нигде нет — строка пропала бы из файла, и InApp показал бы английский. Поэтому база хранит у каждого языка последний утверждённый текст (`approved`), и выгрузка — кнопка и CLI одинаково — берёт его. Новый ключ попадает в файлы после утверждения.
- `approved` считает триггер из статусов: язык утверждён — снимок текущего текста. Одно правило покрывает утверждение, импорт и создание ключа сразу утверждённым, а напрямую колонку не переписать. Существующие строки заполнены по истории: последнее «статус → утверждён» или импорт — так тестовые правки в основной базе (`ADSывыв`, `СКАЧАТЬйцйцйц`) в выгрузку не попадут.
- Ключи нейросети попадают в проект только после утверждения человеком. Это меняет сценарий ТЗ «MCP создаёт ключ → `pull` кладёт его в проект»: между ними теперь утверждение. ТЗ говорит «утверждать будем позже» — отметить для Кирилла.
- Figma не меняется: плагин и ZIP показывают и черновики — дизайнеру нужны тексты до утверждения.
- Кнопка «Выгрузить в код» открывает PR, а не коммитит в основную ветку (решение владельца): мержит человек, как с GitHub-интеграциями Crowdin и Lokalise. Своя ветка `amaya-hub/<набор>` каждый раз пересобирается от основной, поэтому PR один и после мержа содержит только новое; выгружать нечего — свой PR закрывается.
- Сервис пишет только в свою ветку и PR: не в основную ветку, без мержа и удалений. Защиту веток на GitHub для приватных репозиториев на бесплатном тарифе не включить, поэтому это держит код и проверяет тест на поддельном GitHub. Токен — fine-grained только на демо-репозитории.
- Репозитории наборов — в окружении (`NUXT_EXPORT_REPOS`), а не в базе: пара «репозиторий + токен» зависит от стенда, и браузер её не подменит. Для настоящих проектов меняются только две переменные.
- Демо-репозитории свои (`Neverbyyy/amaya-demo-inapp`, `Neverbyyy/amaya-demo-pages-hub`) и содержат только файлы локалей: в рабочие InApp и Pages Hub по ТЗ ничего не отправляем, а код проектов в личный GitHub не кладём.
- Изменённые файлы определяются без скачивания: sha блоба считается локально и сравнивается со списком папки в репозитории (с LF и CRLF). Скачиваются только изменённые — для описания PR и чтобы файл с CRLF таким и остался. GitHub — через REST и обычный `fetch`, без новых библиотек.
- Правку вернули как было — меток нет. Текст, совпавший с последним утверждённым, снова утверждён (триггер). «Перевод устарел» теперь сравнивает тексты, а не номера ревизий: база помнит английский тех ревизий, на которые ссылаются переводы (`source_texts`), и перевод устарел, только если английский сейчас другой. Перевод, сделанный по промежуточной версии английского, после отката по-прежнему устаревший. Ревизии с неизвестным текстом считаются устаревшими, как раньше. Существующие строки починены по истории: каждая правка английского — следующая ревизия.
- Кнопка называется «Выгрузить в код» — термин ТЗ («Выгрузка в код — самое важное»), глагол говорит, что будет по нажатию, и рядом с «Export Figma» читается парой. Она выделена тёмной как главное действие; «Export ZIP» из прототипа остался в шапке обычной кнопкой — по ТЗ его сохраняем.

## Этап 1: тёмная тема

- Тема — две: светлая и тёмная, по умолчанию светлая, без «как в системе» (решение владельца). Настройка — отдельная страница `/settings` в меню слева, чтобы следующим настройкам было где жить; из палитры Ctrl+K тема переключается тоже.
- Режим держит `@nuxtjs/color-mode`, который уже приходит с Nuxt UI, — новой библиотеки нет. Выбор хранится в браузере, класс `dark` ставится до первой отрисовки, поэтому страница не мигает.
- Цвета разметки — смысловые токены Nuxt UI (`text-muted`, `bg-default`, `border-default`…) вместо `gray-*` и `white`: компоненты и наша разметка темнеют вместе, а новые экраны получают тёмную тему даром. Нейтральный цвет Nuxt UI сменён со `slate` на `gray` — тогда токены дают ровно те серые, что были в разметке, и компоненты Nuxt UI больше не синеватые рядом с серым интерфейсом. Светлая тема после замены попиксельно совпала с прежней на 11 экранах. Где точного токена нет, класс получил пару `dark:`; hex-цвета грида стали CSS-переменными.
- Предупреждения (`warning`) — янтарный 700 в светлой теме и 400 в тёмной: жёлтый текст на жёлтой подложке «устарел» не читался.
- Страницы прототипа `/ab-tests` и `/audit-page` не перекрашивал — они вне этапа 1 и в тёмной теме остаются светлыми.

## Этап 1: подсказки при создании ключа

- Ключ вводится в одном поле с подсказками к следующей части, а не конструктором по шагам (решение владельца): с клавиатуры быстрее, ключ можно вставить целиком, а новичку список под полем показывает, что можно дальше. Подсказки — из того, что уже есть: начала из «Как называть ключи», коды из справочника, разделы из дерева; типичные разделы (`paywall`, `onboarding`, `banner`) — только пока своих нет.
- Пока ключ дописывают, ошибок не показываем: красный на второй букве пугал. Красным — только то, что дописыванием не исправить (`legacy.`, язык в ключе, занятое имя), и всё — когда человек ушёл из поля. Что мешает создать, по-прежнему видно у кнопки.
- Список подсказок — свой, а не `UInputMenu`: нужно дописывать часть ключа и продолжать печатать, а не выбирать готовое значение. Разметка по образцу ARIA combobox; Esc закрывает список, а не всю панель.
- `newKeyError` сначала проверяет начало: «legacy» без продолжения — объяснение про импорт, а не «слишком короткий ключ»; в списке допустимых начал для нового ключа больше нет `legacy.`. Сообщение одинаковое в форме, API и MCP.
- Устаревший ключ не занимает имя (миграция `20261030100000_deprecated_frees_name`): «ключ не может быть началом другого» проверяется только среди действующих ключей. Правило нужно, чтобы в JSON раздел не был одновременно строкой, а устаревшие в выгрузку, Figma и ZIP не попадают. Иначе одна пробная строка (`app.farm.banner`) навсегда запрещала бы раздел с тем же именем: удалять и переименовывать ключи нельзя. Обратная сторона — устаревший ключ не вернуть, пока его место занято: база отвечает «не вернуть: его место занял …».
- В форме «Новый ключ» только ключ, описание и теги (решение владельца): текст EN вписывают потом в гриде или через MCP, лимит длины — в панели ключа. ТЗ текст при создании не требует; `POST /api/keys` принимает `en` по-прежнему, но необязательно. Описание оставлено обязательным, как в ТЗ, — в форме, на сервере, в MCP и в базе (решение владельца).
- Куда уйдёт ключ, видно в интерфейсе: у начал в подсказках «Новый ключ» (`app.` — InApp, `web.` — Pages Hub, `common.` — оба), строкой под полем ключа и в панели ключа. Правило «ключ входит в набор» вынесено в `keyInExportSet` (l10n-core) — им же фильтрует серверная выгрузка, поэтому подсказка не разойдётся с тем, что попадёт в PR. Наборы для подсказок — отдельным лёгким `GET /api/export/rules`: `/api/export/sets` ходит в GitHub и для формы и панели тяжёл.

## Рефакторинг central-hub

- Поведение и вид не менялись; цель — одна реализация на правило, меньше кода в компонентах и лишних запросов. Без коммитов (решение владельца), страницы прототипа `ab-tests` и `audit-page` не тронуты (решение владельца) — ошибки typecheck остались только в `ab-tests`.
- Удалено неиспользуемое из прототипа: `AppLogo`, `TemplateMenu`, `RiveKeyboard` с ассетами `.riv` и зависимостью `@rive-app/webgl2`, заглушка `/localizations/tags`.
- Повторы собраны в одно место: `escapeLike` (было 5 копий) — в `l10n-core`; тост ошибки с переходом на вход (12 мест) — `useNotifyError`; копирование с тостом — `useCopy`; даты — `formatDateTime` с общими `Intl.DateTimeFormat` (грид больше не создаёт форматтер на каждую ячейку); «N ключей» — `keysCount`; «есть что утверждать» — `canApproveLang`; вид справочника по началу ключа — `registryKindOf` из `l10n-core` вместо копии в форме.
- Сервер: `defineHubHandler` вместо 14 одинаковых `try/catch` в маршрутах, `rpcCount` для утвердить/пометить/вернуть; выгрузка (`sync.loadKeys`) использует общий постраничный `allKeys`.
- Чистая логика вынесена из компонентов в `app/utils` и покрыта unit-тестами: история ключа (`history.ts`, из `KeyPanel`) и подсказки к ключу (`keySuggestions.ts`, из `CreateKey`). В компонентах остались разметка, фокус и клавиатура.
- Меньше запросов и килобайт: JSZip (97 КБ, 30 КБ gzip) грузится только по «Export ZIP» / «Export Figma»; дерево ключей — один запрос на страницу для дерева, формы «Новый ключ» и окна Figma (было два при загрузке и ещё один на каждое открытие формы); языки — один запрос для грида, очереди и палитры Ctrl+K (`useAsyncData` с общим ключом, грузятся по первому `load()`).

## Статус PR по вебхуку GitHub

- Окно «Выгрузка в код» узнаёт о мерже по вебхуку GitHub, а не опросом (решение владельца). Цена — настройка вебхука в каждом репозитории: для демо — сами, для настоящих InApp и Pages Hub — их админы или вебхук / GitHub App организации. Без вебхука окно всё равно перечитывает статус при возврате на вкладку — локально и пока вебхук не настроен.
- Без таблицы и миграции: вебхук рассылает событие через Supabase Realtime broadcast (`channel.httpSend`, серверный ключ), а «смержен ли последний PR» сервер спрашивает у GitHub при чтении наборов (`findPr`, `lastPr`). Канал публичный — подделать событие может любой с публичным ключом, поэтому в нём только имя набора, и окно в ответ лишь перечитывает статус с сервера.
- Маршрут `/api/github/webhook` открыт без пароля сервиса и защищён подписью `X-Hub-Signature-256` (HMAC секретом `NUXT_GITHUB_WEBHOOK_SECRET`, сравнение за постоянное время); без секрета на сервере — 503. Учитываются только PR из своей ветки `amaya-hub/<набор>` в репозитории этого набора, не из форка; рассылка не дошла — в лог, GitHub получает 200.
- Окно перечитывает «тихо»: старые данные на месте до ответа, без скелетонов; ошибка тихого обновления не заменяет карточку.
- Выгрузку кнопкой сервис объявляет в тот же канал Realtime сам (`notifyExportChanged` после `/api/export/<набор>/push`): окна коллег обновляются сразу и без вебхука, в том числе локально. Вебхук GitHub остаётся для того, что происходит вне сервиса, — мерж и закрытие PR.
- Строка статуса в карточке строится из данных сервера (`lastRun` + `lastPr`), а не из памяти окна о последнем нажатии: у всех одинаковая «PR #11 обновлён · дата · кто». Мерж или закрытие на GitHub важнее строки выгрузки; если PR закрыл сам сервис («выгружать нечего»), показывается строка выгрузки — она объясняет причину.
- Открытые PR видно без открытия окна — бадж с числом в углу кнопки «Выгрузить в код» (`position: absolute` поверх края, чтобы ширина кнопки не менялась, когда PR открыли или смержили), подсказка — какие и кто выгрузил (решение владельца; уведомления всем и строку в шапке не делали — шумно и тесно). Данные — отдельный лёгкий `/api/export/open-prs` (только открытый PR и строка журнала), а не `/api/export/sets` с подсчётом ждущих утверждения. Обновляется по тому же каналу Realtime и при возврате на вкладку.
- Бадж приходит в HTML страницы: последний ответ `/api/export/open-prs` хранится в куке `hub-open-prs`, и сервер рисует бадж по ней. Иначе он появлялся бы только после загрузки страницы и ответа GitHub (0,3–0,7 с). Не localStorage — его сервер не видит, и бадж всё равно появлялся бы после загрузки скриптов. Не запрос к GitHub при отрисовке — он задержал бы всю страницу. Цена — если PR смержили, пока вкладки не было, старый бадж держится до свежего ответа (меньше секунды).
- Подписка на канал `export-pr` одна на вкладку (`useExportPrEvents`): `supabase.channel()` для той же темы возвращает тот же канал, и две независимые подписки (бадж и окно) мешали бы друг другу — повторный `subscribe()` и отписка окна сняли бы подписку баджа.

## Адаптив: планшеты и телефоны

- На телефоне таблица остаётся, а правка — в шторке снизу (решение владельца; список карточек вместо таблицы — вдвое больше работы, правка в узкой ячейке пальцем неудобна). Тап выделяет ячейку, тап по выделенной — шторка: так в таблицах на телефоне, а двойной тап в iOS не всегда доходит как `dblclick`.
- Десктоп от 1280 px не менялся: скриншоты 1920 и 1440 до и после совпадают попиксельно. Мышь и клавиатура — как раньше, правка в ячейке.
- Что видно сразу при загрузке (меню, колонки дерева и панели, ширины колонок грида, высота строк), переключает CSS: сервер не знает ширину экрана, и решение в JS дало бы прыжок после загрузки. Остальное (шторка или колонка, правка в ячейке или в шторке) — `useScreen`: до монтирования он отвечает «десктоп, мышь», как сервер, поэтому гидрация совпадает.
- Размеры грида — CSS-переменные (`--loc-row-h`, `--loc-key-w`, `--loc-lang-w`), виртуализация читает числа оттуда же: брейкпоинты в одном месте.
- Панель и правку грид открывает не в `mousedown`, а сразу после нажатия (`setTimeout`): после `mousedown` браузер ставит фокус на грид, и только что открытая шторка принимала это за уход фокуса и закрывалась.
- Строке фильтров нужен `relative`: скрытые поля внутри `USelect` спозиционированы `absolute`, без него прокрутка вбок их не обрезала, и мобильный браузер расширял страницу до ~1000 px.
- Теги и счётчик ключей в тулбаре — от 1280 px. При 1180 они там помещались только ценой наезда тегов на счётчик; ниже порога они в строке фильтров.
- Шторка разделов не закрывается на папке с вложенными: иначе до них было не добраться (замечание владельца). Закрывают её раздел без вложенных, «Все ключи» и кнопка «Показать N ключей» — число видно ещё до закрытия. Пункты в шторке по 44 px, в колонке на десктопе — компактные, как были.
- Поля ввода на касании — не меньше 16 px правилом в `main.css`, а не `maximum-scale=1` во viewport: тот запрещает и ручное увеличение (на Android), это хуже для доступности.

## Разметка в выгрузке в Figma

- В Figma уходит чистый текст: `<br>` — перенос строки, остальные теги убираются (решение владельца по замечанию Антона). Цвет и жирность части строки переменная Figma не несёт; раскраску плагином отклонили: она держалась бы только до смены языка фрейма и только в плагине, не в ZIP.
- Преобразование — на выходе (`figmaText` в `l10n-core`, общее для плагина и ZIP), тексты в базе не меняются: InApp и Pages Hub нужна их разметка. Плагин переустанавливать не нужно — тексты готовит сервер.
- Перед переносом строки в тексте для Figma — ровно один пробел (решение владельца): таблица Variables показывает значение в одну строку и склеивала строки («appsin»), а показать там `<br>`, а на холсте перенос нельзя — значение у переменной одно. Цена — невидимый пробел в конце строки на холсте; проверить, не сдвигает ли он текст, выровненный по центру.
- Тег снимается по форме (`<` + буква … `>`), а не по списку имён: в InApp вперемешку HTML и разметка Unity TextMeshPro (`<color=#…>`, `<#FF8D24>`, `<size=…>`), а форма ловит и опечатки вроде `</span">` во французском. Тест прогоняет все строки копий `fixtures/legacy` — новый вид разметки в данных он покажет.

## Этап 2, день 1: монорепо, токены, пресет Tailwind, Storybook

- Отдельного репозитория нет: дизайн-система живёт в этом же pnpm-монорепо рядом с сервисом, поверх — Turborepo. `pnpm build` собирает всё с кешем, порядок задаёт `dependsOn: ^build` (токены до Storybook). Переменные `NUXT_*` для сборки сервиса turbo пропускает сам (framework inference для Nuxt), строгий режим окружения оставлен.
- Источник токенов — JSON в формате W3C Design Tokens, раскладка «коллекция → режим» (примитивы, темы, брейкпоинты): так Figma экспортирует переменные, и экспорт Антона заменит временные значения без переделки сборки. Временные значения сняты с пейволлов InApp `cars2/tm11` и `farm/tm9`, у каждого файла пометка «временное».
- Сборка токенов — свой скрипт на ~150 строк без зависимостей, а не Style Dictionary: нужны только ссылки, темы и брейкпоинты. Подключим Style Dictionary, если понадобятся его трансформации.
- В Tailwind попадают только смысловые токены (`--color-cta-bg`), примитивы — нет: компонент не может взять `orange-500` мимо темы. Стандартные палитра, шрифты, радиусы, размеры текста и брейкпоинты Tailwind выключены, шаг отступов — 4 px.
- Тема и размеры экрана меняют переменные `--ds-*` (так их называет Tailwind с `prefix(ds)`) вне слоёв, поэтому они сильнее `@theme`. Брейкпоинты — каскадом min-width: large пишет то, что отличается от medium, хотя в источнике large задан относительно small.
- Пресет — в `@amaya/ui/tailwind.css`, а не в пакете токенов: `@source './components'` указывает на соседнюю папку и работает и из `node_modules`. Сброс стилей — копия нужной части preflight под `:where([data-ds-root])`: нулевая специфичность, хост не задет.
- Отступы между элементами в историях — `ds:space-y-*` (margin), а не `gap`: конвенции InApp запрещают `gap` из-за старых вебвью. Минимальная версия iOS у вебвью — открытый вопрос: Tailwind 4 рассчитан на Safari 16.4+.
- Шрифты — пакеты fontsource (woff2 с кириллицей и unicode-range), а не TTF из InApp: в разы легче, грузятся только нужные символы, пейволлу шрифт нужен сразу.
- `DsRoot` — первый компонент: корень экрана с `data-ds-theme` и `lang`. API Vue 3.3, как в InApp (без `defineModel`, `useTemplateRef`), `peerDependencies: vue ^3.3.4`; линтер на это — вместе с правилами дизайн-системы.
- Тексты Storybook (и потом пейволлов и лендингов) — свой набор выгрузки `ds` (решение владельца): миграция добавила проект и набор, `pnpm l10n pull` кладёт утверждённые тексты в `packages/locales`, продукты берут их при сборке. Сервис показывает набор в «Выгрузка в код: InApp, Pages Hub и Дизайн-система» (`Intl.ListFormat` вместо склейки через «и»).
- Общие ключи для компонентов дня 2 заведены через MCP (`common.button.restore`, `common.link.terms_of_use`, `common.link.privacy_policy`, `common.legal.cancel_anytime`), переводы — из утверждённых строк InApp, статус «от ИИ»: в выгрузку попадут после утверждения. `common.button.continue.default` уже был, помечен устаревшим — вернуть в сервисе.
- `pnpm l10n` берёт `AMAYA_L10N_TOKEN` — токен CLI стенда. Локальный `NUXT_CLI_TOKEN` к стенду не подходит (у стенда свои токены, как `AMAYA_HUB_TOKEN` у MCP), поэтому обёртка его не подставляет.
- Переключатели Storybook — свои `globalTypes` и декоратор, а не addon-themes: нужны «все три темы рядом» и атрибут на корне экрана, а не на `<html>`. Страницы токенов показывают все темы сами (`parameters.themes: false`).
- Состояние тулбара — реактивный объект (`.storybook/env.ts`), а не значения из `context.globals`: рендерер Vue при смене переключателя не пересоздаёт показанную историю, а только заново вызывает декораторы, и захваченные при первом рендере тема и язык не менялись без перезагрузки (нашёл владелец на стенде). Проверка переключателей теперь — через событие тулбара в работающем Storybook, а не через адрес с globals.
- Страница текстов показывает все 9 языков колонками, язык из тулбара подсвечен: так сразу видно, на каком языке нет утверждённого текста.

## Этап 2, день 2: компоненты основы и действий

- Без макетов Антона: поведение и состояния — полностью, вид — с текущих пейволлов Cars 2 в InApp и только через токены. Новые временные токены: цвета заголовка, крестика и второй кнопки, зона нажатия `spacing.touch` (44), размеры иконок, крестика и значков, высота кнопки и толщина обводки заголовка по брейкпоинтам.
- `DsGameTitle` — два слоя одного текста (снизу обводка двойной толщины, сверху заливка), а не `paint-order: stroke fill`, как в InApp: для обычного текста его не понимают Android WebView до Chrome 123, и толстая обводка там съедает буквы. И не SVG-текст — его приходится мерить по ширине для переносов. Слой обводки скрыт от скринридера.
- «Нажато» — атрибут `data-pressed` по `pointerdown` (`usePressed`), а не `:active`: в iOS Safari `:active` без обработчика касаний не срабатывает, а отклик по ТЗ нужен на касании. Цвет нажатия меняется сразу, сжатие — анимацией `transform`.
- Защита от двойного тапа — `useTapGuard`, то же правило, что `useClickCooldown` в InApp (800 мс); у кнопки, крестика и ссылок. Проверено: два быстрых нажатия — одно срабатывание.
- `DsCloseButton` считает задержку от `active` (экран показан), а не от события `mitt` InApp: компонент не знает про окружение. `active=false` сбрасывает отсчёт — повторно открытый экран «как новый». Размер — `min-width`/`min-height` (грабли InApp).
- `DsLegalLinks` и `DsStoreBadges` только отдают события: адреса документов, родительский гейт, восстановление покупок, UTM и аналитика — дело экрана (`paywall-kit`, `landing-kit`). Значок стора и его подпись — снаружи: у Apple и Google они свои для каждого языка.
- `DsBackground` — картинка `<picture>` с `object-fit: cover`, а не `background-image` с `image-set`, как миксин InApp: так работают ленивая загрузка и событие `load` (пейволл говорит «готов», только когда арт загрузился).
- Иконки — свой маленький пакет `@amaya/icons` с путями SVG, без библиотеки: иконки игр нарисует Антон, а пять временных путей не стоят новой зависимости.
- Подписи компонентов для скринридера — ключи `ds.*` в сервисе (`ds.close_button.aria.label` — пример из ТЗ), переводы от ИИ, ждут утверждения. Истории берут тексты только из набора `ds`; «длинный текст» — самый длинный из настоящих переводов ключа, своих строк истории не пишут.
- Картинки для историй (арт Cars 2 из InApp, значки сторов из Pages Hub) лежат в `apps/storybook/public/demo` — ТЗ разрешает копировать файлы рабочих проектов себе; в компоненты они не попадают.

## Этап 2: токены из макетов Cars 2 и Farm

Если тема задала токен, её лесенка целиком своя: Cars 2 на 844 берёт свой small (в макетах 667 и 844 у неё одни стили `SM/*`), а не base/medium.

Где в макете Farm у одной роли разные размеры, взято значение пейволла: подзаголовок героя на 844 — 16 px вместо 14, список на iPad — 28 px, как в макете.
- Заливки, которые бывают градиентом (кнопки Cars 2), — группа `surface` и утилита `ds:surface-*` (`background`), а не `color`: цветовые классы ставят `background-color`, градиент туда не встаёт.
- Капс — токены `case.*` и утилита `ds:case-*`: Farm пишет заголовок экрана, кнопки и тарифы капсом, Cars 2 — нет, а тексты в сервисе — в обычном регистре (правило ТЗ).
- Толщины рамок и обводки букв — группа `line` (рамка кнопки Cars 2 — 3 px, на iPad 4; у Farm 0). Обводку букв кнопки делает тот же двухслойный приём, что у заголовка, — вынесен в `DsOutlineText`.
- Цвет ссылки переехал в `color.text.link`: новый текстовый стиль `text.link` и цвет `color.link` давали один класс `ds:text-link`.
- Цвета нажатия кнопки (`cta.bg-pressed`) больше нет: на градиенте его не сделать, а отклик на касании уже даёт сжатие `transform`.
- ~~Высота главной кнопки Farm — 44, а не 36, как в части кадров: зона нажатия по ТЗ (в варианте On click Антон сам рисует 44).~~ Пересмотрено в день 3: видимая высота 36, как в макете, зона нажатия 44 — невидимым слоем.
- Строка документов — подчёркнутые ссылки без точек, как в обоих макетах; промежуток — полями ссылок, не `gap`.

## Этап 2, день 3: пейволлы Cars 2 и Farm на дизайн-системе

- Варианты InApp, которые повторяют макеты, найдены по текстам и по логике. **Cars 2** — `ios/as/cars2/tm11/pw-slider`, вариант B: последний тест с раскладкой «цена в неделю + цена за год». В ua1, ua2 и tm10 отличаются почти только ID продуктов. **Farm** — `ios/as/farm/tm4`, вариант B: `pw-switch` (продукты `start.*`, активный тумблер «Free trial», «Just {0}/year») — «On start», и `pw-trio` (продукты `tap.*`, «ANY PLAN FREE FOR 3 DAYS») — «On click». В tm6 и tm8 тумблер закомментирован, поэтому они не подходят. Продукты, события и смысл текстов — как в этих вариантах, меняется только вид.
- Один интерфейс окружения `PaywallEnv` — как InApp: экран не знает про `mitt`, сторы и `uniwebview://`. Покупка — обещание с итогом (успех, отмена, ошибка). Так экран не держит своё состояние «идёт покупка» отдельно от InApp. Протокол InApp — отдельная реализация (`createUniwebviewEnv`), на ней работает `apps/inapp-preview`. Родительский гейт и оверлей загрузки делает сам InApp, поэтому их нет в протоколе: внутри InApp будет третья реализация — поверх его `mitt` и `productsStore.buy`.
- «Готов» — только после арта, шрифта и цен, а не сразу при монтировании, как в InApp: по ТЗ экран появляется целиком. Если арт не загрузился за 5 с, «готов» всё равно уходит, иначе экран не покажут вовсе. Нет цены у нужного продукта — «закрыть» без «готов» (в InApp была бы цена «$—»).
- Купленным считаются активные подписки и разовые покупки. В InApp `isAlreadySubscribedById` смотрел только подписки, а наборы машин Cars 2 — разовые.
- Цена «в неделю» — `@amaya/pricing`, а не копия `countWeekPriceFromYearly`: та же формула (год / 52), но знаков после запятой столько же, сколько у цены стора («$1.00», а не «$1»). Валюта, разделители и арабские цифры остаются как в строке стора. Без `Array.prototype.at`: его нет в вебвью iOS до 15.4.
- Новый пейволл — конфиг, а не вёрстка. Два шаблона в `paywall-kit` (`PwHeroSlider` для Cars 2, `PwPlusSplit` в режимах `switch` и `trio` для Farm) и конфиг экрана: тема, продукты по сегментам InApp (`t1`, `u`, `ut1`, `wout1` — из имени варианта), ключи текстов, арт. Farm собран без новых компонентов, только шаблон и конфиг.
- Папки экранов лежат в `apps/inapp-preview/src/variants/ios/as/<игра>/ds1/<экран>/`, как варианты InApp: `index.vue`, `config.ts`, `presets.ts` и свой арт. `ds1` — первый тест на дизайн-системе. Отсюда же их показывает Storybook (раздел «Экраны»).
- Арт Cars 2 — из InApp: те же картинки, уже нарезанные по конвенции 12 файлов (25 МБ, в основном PNG-запаски для вебвью без webp — старые iPad на iOS 12). В Figma только исходники. Для слайдов Amaya Plus в InApp — анимации Spine с CDN. Их статичные версии (InApp показывает их старым устройствам) нарезаны через canvas в Chrome без новой зависимости: small 300, medium 360, large 512, @2x.

- В попапе тарифов Cars 2, когда триал уже был, по умолчанию выбран первый видимый тариф. В InApp выбор оставался на скрытом тарифе с триалом, и кнопка покупала его.

- Рамка карточки тарифа и строки триала рисуется тенью внутрь, а не `border`. У выбранной карточки рамка толще (в Cars 2 1 → 3 px), и с `border` содержимое сдвигалось бы.
- Тексты — 65 новых ключей, заведены через MCP сервиса скриптом. Переводы — из текстов InApp с тем же смыслом: подстановки по имени, без `<br/>`, обычный регистр. Общее у всех игр — в `common.*`: кнопки, тарифы, цены, триал. Amaya Plus — в `common.plus.*`: это подписка на все приложения, а не одна игра. Своё у Cars 2 — только заголовок и карточка оборота (`app.cars2.paywall.*`). Заголовок Cars 2 собран из частей («All cars» / «and {apps}» / «in ONE subscription!»), как в InApp: в двух местах он разбит на строки по-разному.
- Множественное число — формами через «|», у русского три формы (`pluralRules` в `@amaya/locales`). У ключей с формами нет лимита длины: сервис считает его по всей строке со всеми формами.
- Капс «FREE» и «ONE» внутри фразы оставлен в тексте: это выделение слова, а не стиль. CSS-капс (`case.*`) делает целые строки.
- `DsPlanCard` — кнопка с `role="radio"` внутри `role="radiogroup"`: стрелки переводят выбор, Tab попадает только в выбранную. Нативные радио плохо стилизуются, а выбор нужен на касании.
- `DsSlides` и `DsCarousel` — нативная прокрутка со `scroll-snap`, без Swiper, как в InApp: свайп пальцем — системный и плавный на любом Android. Автопрокрутка встаёт на паузу вне экрана, под пальцем и при `prefers-reduced-motion`.
- Состояние тулбара Storybook переехало в `@amaya/ui/stories`: его читают и истории пакетов, и экраны из `apps/inapp-preview`.
- Экран не должен вылезать по высоте ни на каком устройстве. На 1025×520 Cars 2 и Farm брали размеры iPad (карточка 686×474) и не помещались. На iPhone SE в альбомной (568×320) Cars 2 прятал «More plans», а попап тарифов вылезал за верх. Решение в два слоя:
  1. Размеры iPad (`large`) — только на экране от 1024 px в ширину **и** от 600 px в высоту: токены, `IMAGE_MEDIA` для арта и вариант `ds:large:` (`@custom-variant` в пресете, у переменной брейкпоинта Tailwind нет высоты). Широкое, но низкое окно получает размеры телефона. Позже ширина снижена до 844 — см. «Онбординг Farm по макету».
  2. `DsFit`: экран раскладывается в своих размерах, и если он выше места, уменьшается целиком через `transform: scale` (не меньше 0,6). Ничего не обрезается и не переносится иначе, чем в макете. Масштаб считается до первой отрисовки и при изменении размера или содержимого (смена языка). Обёрнуты ряд карточек Cars 2, попап тарифов и правая половина Farm. Не `zoom`: у `transform` одинаковое поведение во всех движках и нет влияния на вёрстку снаружи.

## Rive

- Рантайм — `@rive-app/webgl2` ровно 2.39.2, как в InApp, а не последний 2.49: анимация в Storybook ведёт себя так же, как потом в продукте. Альтернативы нет — .riv играет только рантайм Rive. В `@amaya/ui` он необязательная peer-зависимость: внутри InApp `DsRive` возьмёт его рантайм и уже прогретый wasm, а не потянет вторую копию.
- wasm (2,6 МБ) — со своего адреса через `configureRive`, а не с unpkg, откуда его по умолчанию берут рантайм и InApp: вебвью без внешней сети или с медленной сетью иначе остаётся без анимации. Запасной `rive_fallback.wasm` — тоже свой; качается, только если основной не поднялся.
- Рантайм грузится динамическим импортом, когда первый `DsRive` подъезжает к экрану (запас 200 px), — страницы без анимации его не качают. За экраном анимация на паузе: сам рантайм останавливается только на скрытой вкладке. Плотность холста — не больше 2x, как у картинок.
- Запуск — следующей микрозадачей после `onLoad`: команды воспроизведения рантайм принимает только после него, а `reset()` внутри `onLoad` в 2.39 уходит в бесконечную рекурсию и вешает страницу (найдено на этом файле, проверено на голой странице).
- Стейт-машина по умолчанию — первая у артборда, как в редакторе Rive. Играет и встаёт только она, по имени: `play()` без имени запустил бы заодно первую анимацию файла, которую рантайм создаёт на паузе.
- Привязка view model — по пропу `bind-view-model`, а не всегда: на запрос view model у артборда без неё wasm пишет ошибку в консоль. В `animation-paywall-cars.riv` лежит пустая `ViewModel1`, ни к чему не привязанная. Просмотр в Storybook сам проверяет артборд и вставляет проп в строку подключения, когда он нужен.
- В Storybook у Rive одна история — просмотр файла; отдельной истории с постером нет (решение пользователя). Проп `poster` у `DsRive` остаётся: ТЗ лендинга требует сначала картинку и картинку на месте анимации, если та не загрузилась.
- Файлы для Storybook — в `apps/storybook/rive/`: положил — анимация появилась в списке (`import.meta.glob`), без правки историй. Файл, который взял экран, лежит у арта экрана, как в InApp, и просмотр находит его там же — без второй копии.

## Лендинг Cars 2

- Макет Антона (Figma `38:57`, кадры 375 и 768) — узбекский: бесплатный вариант лендинга `l1` из Pages Hub. Языков остаётся 9 (решение пользователя): источник — английский по смыслу макета, переводы — ИИ; `/cars2` — английский. 40 ключей (`web.lp_cars2.*`, `common.button.play_free`, `common.legal.all_rights_reserved`, `ds.rating.*`, `ds.video.*`) заведены через MCP со статусом «от ИИ»; авторы отзывов — тоже ключи (строк в коде нет).
- Английский заголовок — «Congrats!», а не «Congratulations!»: при 44 px длинное слово не помещалось в «каплю» и на узком телефоне вылезало за экран. На случай длинного языка заголовок переносит слово, а не вылезает.
- Сверх макета, по ТЗ (решение пользователя): значки App Store и Google Play под кнопкой первого экрана и блок FAQ (5 вопросов по смыслу `l1`, вид — как карточки отзывов). Закреплённой кнопки на странице нет; блок `LkStickyCta` в `landing-kit` есть, включается конфигом.
- Кнопка ведёт в стор по платформе: iPhone/iPad — App Store, Android — Google Play, компьютер — прокрутка к значкам. UTM: в App Store — `utm_*` и `ct` (кампания: Apple читает только его), в Google Play — одной строкой в `referrer`.
- Rive на первом экране сначала был (шарики из `animation-paywall-cars.riv` в углу поверх арта), потом убран: в макете его нет (решение пользователя). Гонка из того же файла тоже не подошла: её рисовали для карточки пейволла — в центре белое свечение под текст, енот уходит под «каплю». Возможность осталась: `hero.rive` в конфиге (во весь арт или в углу) — когда Антон нарисует анимацию для лендинга. Файл `.riv` вернулся в `apps/storybook/rive` («Анимации → Rive»).
- Интерактив (`LkInteractive`) монтируется через 2,5 с после загрузки и в простое, на 2G/3G и с экономией трафика — не грузится: рантайм Rive — 2,6 МБ wasm и разбор `.riv` на 1,2 МБ. Сразу после загрузки он делал Lighthouse 47 (LCP 8,2 с, блокировка потока 1,7 с), отложенный — 90.
- Модуль `@amaya/nuxt` снимает подсказки `prefetch`, которые Nuxt ставит на все файлы сборки: иначе браузер в простое качал wasm Rive, ролик (6 МБ) и png-запасы картинок.
- Тексты на лендинге — только языка страницы (`@amaya/locales/lazy`, отдельная точка входа: когда один модуль грузит JSON и статически, и лениво, сборщик не выносит их в чанки). Чанк приложения — 99 КБ вместо 109 КБ, и он не растёт с каждым новым ключом.
- Конвенция картинок получила размер `wide` (от 640 px, брейкпоинт раскладки лендинга): арт первого экрана на телефоне и на планшете обрезан по-разному, на телефоне он теперь 72 КБ вместо 108 КБ. Пейволлов это не касается: `wide` берётся, только если есть файлы `-wide`.
- Брейкпоинт раскладки `ds:wide:` — 640 px, а не токенами 844/1024: портретный планшет 768 по ширине ещё «маленький», а макет 768 — две колонки по 286. Десктопа в макете нет: колонка 768 по центру белой карточкой на `color.lp.page` — как кадр в макете.
- Токены лендинга — отдельные `lp.*` (цвета, заливки, тени, стили текста, размеры), а не тема `cars2` пейволла: у пейволла Cars 2 ссылки белые поверх игры, у кнопки белая рамка и обводка букв, у лендинга — синие секции и кнопка без рамки. Имена стилей текста и цветов не совпадают (`lp-note` и `lp.deep`): иначе класс `ds:text-*` неоднозначен.
- Звезда и кавычка — иконки `@amaya/icons` с цветом из токена, а не картинки из макета: чётко на любом экране и без запросов. Цвет взят из исходных картинок макета — переменных у них нет.
- Постер видео — первый кадр самого ролика (заставка Kids Cars 2), а не картинка из макета: та — скриншот YouTube с впечатанной кнопкой «▶». Ролик и значки сторов — копии из Pages Hub (`Cars2_1280x720.mp4`, английский значок App Store из `l3`).
- Lighthouse (мобильный, prerender-сборка локально): с реальным замедлением сети и процессора — 92, LCP 2,4 с, CLS ≈ 0; в режиме моделирования — 90, LCP 3,4 с: локально JS выполняется до первой отрисовки, и модель считает его частью пути к LCP. Доступность 96: контраст белого текста на голубом из палитры макета — вопрос к Антону.

## Claude Code собирает из дизайн-системы

- Правила для Claude Code — `.claude/CLAUDE.md`, а не корневой `CLAUDE.md`: корневой — локальная копия ТЗ, в репозиторий не идёт (решение пользователя). Исключение в `.git/info/exclude` сужено с `CLAUDE.md` до `/CLAUDE.md` — иначе не попадали бы и `CLAUDE.md` пакетов.
- Линтер дизайн-системы — свой маленький плагин (`tools/eslint/ds.mjs`, два правила: классы `ds:` и сырые значения) плюс готовые правила eslint-plugin-vue (`no-bare-strings-in-template`, `no-restricted-html-elements`). Отдельного пакета не заводили: правила нужны только этому монорепо. Строка в коде считается классами, только если в ней есть `ds:` — иначе ловились бы сравнения (`variant === 'lp'`). `<style>` линтер не видит — это остаётся на ревью.
- Запрет `<img>`, `<video>`, `<canvas>` — только для блоков, шаблонов и экранов: сами `DsImage`, `DsVideo` и `DsRive` эти теги и реализуют. Истории и демо-данные Storybook — инструменты, правила продукта на них не действуют.
- Манифест — из кода (`vue/compiler-sfc`: JSDoc, пропсы с комментариями и значениями по умолчанию, события, слоты), без vue-component-meta: хватило того, что уже есть в Vue. Проверка свежести — в lint пакета `ui`; у задачи в turbo входы — и `paywall-kit`, и `landing-kit`, иначе кеш пропустил бы устаревший манифест.
- Figma для Claude Code — REST-инструменты (`tools/figma`), а не MCP: на тарифе Starter у MCP 6 вызовов в месяц. Нарезка арта и скриншоты — через `puppeteer-core` и установленный Chrome: новой зависимостью без скачивания браузера; sharp и т. п. не понадобились — webp делает canvas.
- В корень добавлены devDependencies `vue-eslint-parser` (тесты правил линтера; сам линтер Vue работает на нём же) и `puppeteer-core` (инструменты выше).

Новых компонентов и токенов не понадобилось; линтер и типы чистые; 4 ключа заведены через MCP. 844×390, шаг 1 — почти один в один с макетом; на шаге 2 заголовок переносится иначе (ручной перенос макета заменён на `ds:text-balance`) и крестик на арте другого цвета.

Старый ключ входит в набор `ds` и уйдёт в `packages/locales` — пометить устаревшим в сервисе (через MCP нельзя: это право человека). ## Этап 3: эмулятор InApp, сценарии, Rive на Cars 2, лендинг Farm

- Эмулятор — родительская страница, экран — в iframe по настоящему протоколу InApp (режим hyper: `postMessage {instance:'inapp', url:'uniwebview://…'}` туда, `{eventName, data}` обратно), а не заглушка окружения, как в Storybook: так проверяется ровно то, что пойдёт в InApp, — разбор AppData (`toInAppData` → `fromInAppData`), очередь команд, `loaded` → данные → `ready` → `open`. Storybook остаётся витриной для Антона, эмулятор — проверкой поведения.
- Лог эмулятора не только пишет, но и подозревает: одинаковая команда ближе 600 мс, второй `buy` до итога, `buy` при закрытом экране, `ready` до данных и повторный на те же данные, `close` дважды. «Закрылся без ready» — пояснение, а не ошибка: так экран без продукта и должен себя вести.
- Состояние эмулятора — в адресе (`replaceState`): у каждого сценария своя ссылка, как требует ТЗ. Без новых зависимостей: Vue и свой CSS; это инструмент, правила продукта (ключи, токены) на него не действуют, как на истории Storybook.

## Плагин Figma: мгновенное обновление и фоновый режим

- Живое обновление плагина — через Supabase Realtime, а не опросом раз в 5 с. Сначала выбрали опрос; пересматриваем, потому что владелец попросил обновлять сразу. Событие — только сигнал «ключ изменился»: тексты плагин всё равно берёт запросом `texts?since=` по своему токену. Так источник текстов один, а Figma получает тот же чистый текст, что и раньше.
- Клиент Realtime в окне плагина свой, около 80 строк протокола Phoenix (`vsn=1.0.0`, JSON, как у realtime-js), без supabase-js: у плагина нет сборки и зависимостей. WebSocket есть только в окне, поэтому подписка живёт там и пересылает ключи основному коду пачкой раз в 100 мс; основной код отбрасывает чужие разделы и собирает события в один запрос через 300 мс. Подписка готова только после сообщения `system` от `postgres_changes`, heartbeat — раз в 25 с, без ответа на прошлый — переподключение. Если что-то сломается при обновлении Supabase, смотреть сначала сюда.
- В архив плагина сервис кладёт адрес Supabase и публичный (publishable) ключ — те же, что у грида: ключ только читает (`20261028000002_lockdown.sql`), архив скачивается за паролем, секретного ключа и токенов в нём нет. Нет адреса — плагин работает опросом, как раньше.
- Опрос остаётся: пока Realtime не на связи — раз в 5 с с удвоением паузы при ошибках, на связи — страховочный раз в минуту: событие Realtime может потеряться. После подключения — сразу один запрос: правки, сделанные, пока шло подключение, не теряются.
- «Следить в фоне» — окно скрывается `figma.ui.hide()`, подписка в скрытом окне работает дальше, итоги — уведомлениями Figma. Слежение заканчивается с закрытием файла или запуском другого плагина. Совсем без запущенного плагина нельзя: код плагина работает, только пока он запущен, а запись переменных через REST API Figma есть только на Enterprise.
- Проверено: тест плагина на поддельном `figma` (21 случай, в том числе пачки событий и фон); окно в Chrome против поддельного сервера Phoenix (подписка, пачки, обрыв, heartbeat, стоп); локальный Supabase — правка строки доходит до окна за 0,1–0,5 с; основной Supabase — подписка публичным ключом (только чтение). В настоящей Figma — не проверено, проверяет человек.

## Совместная работа в сервисе: ключи коллег сразу и присутствие

- Грид слушает в Realtime не только правки, но и новые строки: новый, помеченный устаревшим и вернувшийся ключ появляется и пропадает сразу. Подходит ли строка под выборку, решается в браузере теми же условиями, что запрос к базе (поиск по ключу и всем переводам, теги, статусы, «устарел», «нет перевода», неделя, раздел). Строка, которая перестала подходить после правки, остаётся до перезагрузки — иначе она пропадала бы из-под курсора у того, кто её правит; уходят только ключи, помеченные устаревшими (или вернувшиеся — при просмотре устаревших).
- Место новой строки — порядок базы. Он совпал с `Intl.Collator('en')` на всех 2902 ключах основной базы, а побайтовое сравнение расходится уже на сотой строке (`1_week_plan` и `1000+…`). Строка дальше загруженной части не вставляется — придёт со следующей страницей; страница, сдвинутая такой вставкой, не задваивает строку. События пачкой (импорт, «Утвердить всё») перестраивают список раз в 100 мс.
- Курсор и прокрутка грида держатся за ключ: строка коллеги выше курсора не переносит курсор и открытую панель на соседний ключ, строка выше видимой части не сдвигает таблицу. Браузерная привязка прокрутки (`overflow-anchor`) у грида выключена: Safari её не знает, а Chrome сдвигал бы таблицу второй раз.
- Присутствие — Supabase Realtime Presence на канале `hub-presence`, без базы: каждая вкладка шлёт имя, рабочий адрес и ячейку, которую правит (грид, шторка, очередь). Страницу, где человек, больше не шлём и не показываем (просьба владельца) — заодно переходы между страницами не тратят лимит присутствия. Человек — это адрес из Google: тёзки с разными адресами — разные люди, вкладки одного адреса — одна запись; у вкладок прежней версии адреса нет, их узнаём по имени. Адрес виден в списке «Сейчас в сервисе» и в подсказке над кружком (просьба владельца). Метка — подсказка, не блокировка: блокировки зависали бы, если человек закрыл ноутбук посреди правки, а от потери правок уже защищает проверка 409. Своё имя (и свои другие вкладки) человек не видит; цвет — от имени, у всех коллег одинаковый.
- Канал присутствия, как и подписка грида, открыт публичному ключу, а ключ есть в HTML любой страницы, включая `/login` без входа. Тот, кто его достанет, увидит имена и рабочие адреса тех, кто сейчас в сервисе, и какие ключи они правят (сами ключи публичный ключ и так читает), и может прислать ложную метку. На данные и права это не влияет. Вход через Google этого не закрыл: он свой, а не Supabase Auth, а приватным каналам нужна сессия Supabase. Закрыть — отдавать браузеру ключ только после входа или выдавать вошедшим короткий токен Supabase.
- Метка «правит» застревала (замечание владельца): у Supabase Realtime лимит на клиента — 5 обновлений присутствия (track / untrack) за 30 с, на шестом сервер отвечает «Client presence rate limit exceeded» и закрывает канал, а вкладка не переподключалась. Первая версия слала через присутствие каждую смену ячейки. Теперь присутствие — только редкое (имя и адрес, устройство, время входа), не чаще раза в 7 с, уходит последнее состояние; ячейка — сообщением (broadcast) сразу. Сообщения не хранятся, поэтому пока человек правит, сообщение повторяется раз в 15 с, новая вкладка просит остальных прислать своё («hello»), метка без повторов дольше 40 с и метка ушедшего человека пропадают. Закрытый канал вкладка открывает снова (через 5, 15, 30 с). Проверено (`presence-repro`): 30 быстрых переходов между ячейками без единого отказа сервера, у коллеги метка всегда та, что сейчас; зашедший позже видит чужую правку; закрыл вкладку посреди правки — метка пропала за доли секунды.
- Шапка: «N онлайн» считает людей (по адресу, у прежних вкладок — по имени) вместе с собой; у каждого кружка — подсказка (имя, адрес, устройство, сколько в сервисе, что правит), по нажатию — список всех (подсказки на касании не работают, поэтому список — по нажатию, а не по наведению). Кружки — своими элементами, а не UAvatarGroup: группа рассчитывает, что её дети — сами аватары, и с обёрткой-подсказкой работает ненадёжно. В кружке — одна буква (решение владельца: полное имя видно при наведении), цветов 12 вместо 8 — реже два человека одного цвета. Время — «в сервисе 12 мин», без «зашёл / зашла».
- Проверено двумя людьми в разных контекстах браузера на локальном Supabase (`collab-check`): шапка, метка на ячейке и в очереди (появляется и пропадает за доли секунды), новый ключ у коллеги через 0,2–0,5 с на своём месте, курсор не перескакивает, таблица не дёргается, ключ из другого раздела в выборку не попадает; функции присутствия — `tests/unit/presence.test.ts`.

   - есть неиспользуемые параметры и поле `languages` в ответе Figma.
6. **Безопасность:**
   - не показывать нейросети сырой текст ошибок базы;
   - сравнивать `/mcp` в middleware точно;
   - ограничить частоту входа.
7. **CLI:** битый lock-файл даёт стек вместо понятного сообщения.
8. **Ошибки Supabase в клиенте** выводить через `notifyError` — иначе изменится текст тоста.
9. **`pendingApproval`** двоит ключи, если наборы пересекутся. Сейчас не пересекаются.
10. **База:**

## Вход через Google вместо общего пароля

- **Пароль убран совсем** (решение владельца), вход — только через Google. Прежние парольные сессии без адреса входом больше не считаются: после выкатки каждый один раз входит через Google.
- **Превью PR на Vercel закрыты** — это принято. У каждого превью свой адрес, а Google возвращает только на адреса, прописанные у OAuth-клиента (стенд и localhost).
- **Кого пускать — любой рабочий аккаунт Google Workspace компании, без списка людей** (решение владельца). Просто «любой аккаунт Google» отклонён: адрес стенда открыт всему интернету, и войти смог бы кто угодно — с токенами MCP и Figma, правкой строк и PR через выгрузку.
  - Сверяется поле `hd` токена (домен Workspace аккаунта), а не окончание адреса: так советует Google. Обычный gmail и аккаунт Google, заведённый на рабочий адрес без Workspace, `hd` не получат. Адрес — только подтверждённый (`email_verified`).
  - Домен `amayasoft.uz` (из адреса коммитов) — значение по умолчанию `authDomain` в `nuxt.config`: не секрет, отдельная переменная не нужна; другой — `NUXT_AUTH_DOMAIN`. В Google он же уходит параметром `hd`, и окно выбора сразу предлагает рабочие аккаунты.
  - Если почта компании не на Google Workspace, войти не сможет никто — тогда нужен список адресов (вариант был и отклонён).
- **Имя — только из профиля Google**, сменить нельзя. Шага «Представьтесь», `/api/auth/name` и `NAME_REQUIRED` больше нет.
- **На главной — имя без фамилии** (просьба владельца): `given_name` из Google, а не первое слово полного имени — порядок «Фамилия Имя» в профиле его не путает. Правки и боковая панель — по-прежнему полным именем. Сессии, начатые до этого, берут первое слово полного имени, перелогиниваться не нужно.
- **Без библиотеки.** `nuxt-auth-utils` заменил бы нашу сессию и добавил модуль ради одного обработчика. Поток OpenID Connect — две ручки (`/api/auth/google`, `/callback`) и чистые функции в `server/lib/google-auth.ts`, проверенные тестами на поддельном `fetch`, как выгрузка в GitHub.
- **Защита потока.**
  - `state` (подделка запроса), `nonce` (подмена токена) и PKCE S256 лежат в отдельной зашифрованной cookie `hub-oauth` на 10 минут. Она стирается при первом же возврате.
  - Адрес возврата после входа — только внутренний путь.
  - При входе в сессии остаются только адрес и имя нового входа: прежние поля стираются явно. `clear()` перед `update()` в h3 не помогает — `update()` перечитывает старую cookie из запроса и дописывает в неё (нашла сквозная проверка).
- **Подпись id_token не проверяется.** Токен получен сервером напрямую от token endpoint Google по TLS — OpenID Connect Core 3.1.3.7 это допускает, и не нужно тянуть ключи Google. Проверяются издатель, получатель (наш client id), срок и `nonce`.
- **Одно правило на каждую проверку.** «Вошёл» — `hubUser` (адрес и имя из Google): им пользуются middleware, `requireHubUser` и `/api/auth/me`, раньше middleware смотрел только адрес. «Куда вернуть после входа» — `internalPath` в `shared/utils/auth.ts`, общий для сервера и страницы входа. Cookie `hub` и `hub-oauth` настраивает один помощник, отличаются они только именем и сроком.
- **Автопроверки входят без лазейки в коде.** Cookie сессии шифрует сам скрипт ключом `NUXT_SESSION_PASSWORD`. Отдельного «тестового входа», который мог бы попасть на стенд, нет.

## Теги — свой список, правый клик «Добавить тег»

- **Тег — строка таблицы `tags`, а не только значение в массиве ключа** (просьба владельца: создавать теги отдельно и потом добавлять в них ключи). У ключа по-прежнему массив `localizations.tags`: на нём уже стоят фильтр, поиск MCP, история и Realtime, переделывать их на связующую таблицу незачем.
- **Правило в базе, как у кодов справочника:** триггер не даёт поставить ключу тег, которого нет в списке, и больше 20 тегов; `check` у таблицы — имя 1–40 символов без запятой (через неё теги идут в адресе фильтра `?tags=a,b`), уникальность без учёта регистра. Так опечатку не поставить ни формой, ни нейросетью, ни мимо сервера. Существующие теги ключей миграция перенесла в список.
- **Несколько тегов в фильтре — ключи с любым из них** (`overlaps`, в Postgres `&&`, тот же GIN-индекс по `tags`), а не только со всеми сразу: раньше `contains` давал пустую таблицу, если выбранные теги стоят у разных ключей (замечание владельца). То же правило — у строк, пришедших от коллег через Realtime, и в экспортах ZIP и Figma: они берут выборку тем же запросом.
- **Нейросеть ставит только существующие теги:** видит их в `list_registry` (`kind: tag`), создавать не может — это люди делают в «Все теги» или в меню правого клика. Формат ответа `list_registry` прежний — строки `{ kind, code, title }`.
- **Где управлять — в фильтре «Все теги», отдельной страницы нет** (решение владельца: сначала была страница «Теги», потом её убрали). Там же создать — кнопкой «Создать тег», закреплённой внизу под списком (просьба владельца; строки «создать» внутри списка нет, чтобы не было двух одинаковых пунктов): с набранным в поиске новым именем создаёт его сразу, с пустым поиском — окно с полем; Enter без совпадений тоже создаёт, а при совпадениях выбирает найденный тег, как обычно в списке. У тега — число ключей, при наведении ✎ и 🗑; переименование и удаление — окном с подтверждением: поле внутри выпадающего списка спорило бы с его поиском и клавиатурой. На касании кнопки видны всегда (`pointer-coarse`), нажатие на них не выбирает тег в фильтре. Число и кнопки лежат в одной ячейке и меняются только прозрачностью, место под кнопки занято заранее, кнопки не выше строки (20 px): раньше кнопки `xs` (24 px) появлялись вместо числа, и пункт при наведении вырастал — список прыгал (замечание владельца). Новый тег в фильтре не выбирается — иначе выборка сразу стала бы пустой. Ключи добавляются только в таблице — выделить → правый клик (решение владельца); отдельной кнопки на плашке выделения нет.
- **Теги у ключа в таблице — иконкой, сами теги — подсказкой при наведении** (решение владельца). Пробовали метки справа от имени (обрезали имя) и второй строкой под ним (не понравилось). Иконка занимает ~20 px у правого края колонки ключа, есть только у ключей с тегами; подсказка (`UTooltip`, как у кружков присутствия) показывает все теги метками. На касании подсказок нет — теги видны в панели ключа. Иконка появляется и пропадает сразу и у коллег — теги приходят в строках грида и через Realtime.
- **Меню правого клика — `UContextMenu` Nuxt UI, без библиотеки.** Поиск и создание — полем в слоте `content-top` подменю: в меню Nuxt UI поиска нет. Буквы в поле не уходят в поиск Reka по пунктам (`stopPropagation`), ↓ переходит в список. Галочки не закрывают меню — можно отметить несколько тегов подряд. Внизу подменю — кнопка «Создать тег», как в «Все теги» (просьба владельца): с набранным именем создаёт и сразу ставит тег, с пустым полем открывает то же окно «Новый тег», что и «Все теги» (`TagNameModal`, просьба владельца), и тег из окна сразу ставится этим ключам; строки «создать» в самом списке нет. Меню Reka нельзя закрыть снаружи, а окно поверх открытого меню спорило бы с ним за фокус — поэтому кнопка закрывает меню через Esc (он закрывает его целиком, с подменю), окно открывается, когда меню закрылось, а после окна фокус возвращается в таблицу. Список тегов в подменю — не выше ~10 строк (`max-h-80`), дальше прокрутка; поле поиска и «Создать тег» остаются на месте. Окно имени не перепроверяет имя, пока сохраняет и после успеха: новый тег попадает в список раньше, чем окно закроется, и иначе на долю секунды мелькало «Тег уже есть» (замечание владельца). Режим окна (новый тег или переименование) и подписи — снимок на момент открытия: «Все теги» сбрасывает переименуемый тег сразу при закрытии, и без снимка окно на время анимации становилось «Новым тегом» с «уже есть» на своём же имени (тоже замечание владельца); закрытое окно имя не проверяет вовсе. Тег ставится в строке сразу и откатывается, если сервер отказал.
- **Для каких ключей:** строка по которой кликнули, а если она среди выделенных — все выделенные (как в Finder и Gmail). У части из них — «2 из 5», клик ставит тег всем.
- **Правая кнопка только делает строку активной**: раньше любое нажатие на колонку ключа открывало панель, и правый клик открыл бы её вместе с меню.
- **Быстрые галочки не мигают** (замечание владельца): событие Realtime о первой галочке приходило раньше, чем сервер записывал вторую, и затирало её на мгновение. Правки из меню держатся поверх тегов из событий, пока не придёт событие с `updated_at` не раньше времени записи — его отдаёт ответ `POST /api/keys/tag`. Сверка по совпадению тегов не годится: события отстают на несколько правок, и старое могло совпасть случайно. Запросы уходят по одному, в порядке кликов, иначе «поставить» и «снять» одного тега могли бы дойти до базы наоборот. Нет события (у ключа ничего не поменялось) — правка уходит через 5 с.
- **С клавиатуры** — клавиша меню и Shift+F10: браузер присылает `contextmenu` в сам грид, меню открывается у активной строки (`data-active`). На телефоне — долгое нажатие (так умеет Reka); `prioritizePosition` держит меню и подменю в пределах узкого экрана, иначе они уезжали за левый край.
- **Переименование и удаление проходят по всем ключам, и по устаревшим** (их могут вернуть), и пишут историю каждому ключу — с автором. Ставить и снимать тег у устаревших нельзя, как и править их тексты.
- **Чтение — публичным ключом:** `tags` (`select`) и `get_tags()` со счётчиками добавлены в белый список `security.test.ts` осознанно — список со счётчиками нужен фильтру и меню в браузере. `get_unique_tags()` читает список, поэтому в фильтре видны и пустые теги. Список перечитывается при открытии фильтра и меню: Realtime ради редких новых тегов не нужен.
